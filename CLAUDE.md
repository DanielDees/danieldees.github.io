# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A first-person browser horror game — "NOCLIP: Escape the Backrooms" — vibe-coded with Claude Fable 5 / Claude Mythos 5. Vanilla JS ES modules with Three.js r128 from CDN; no build system, no package manager, no compilation, no image or audio assets (everything is procedurally generated).

Three levels as of v3.0.0: **LEVEL 0** (the yellow backrooms maze), **THE END** (the infinite library, entered when the exit elevator's brakes fail) and **THE NEST** (the fungus-lit cave below the library's dug stair). `STATE.level` (0/1/2) picks the active update path; the renderer, light pool, audio buses, interaction/focus, HUD and cutscene systems are shared across levels. Versioning: major = number of levels, minor = refinements to existing levels. Per-level lore documents (menu wiki entry + in-world found document, parse-ready) live in `lore/` — see `lore/README.md` for the format contract.

## Running locally

The game uses ES modules, so it must be served over HTTP (opening `index.html` via `file://` will not work):

```
npx serve .
# or
python -m http.server
```

GitHub Pages serves `index.html` at the repo root as the live site.

## Architecture

`index.html` is markup only (HUD + overlay screens); `css/main.css` holds all styling; game code lives in ES modules under `js/`, entry point `js/main.js`:

- **`utils.js`** — `$`, `clamp`, `lerp`, `angLerp`, `rand`, `hash` (the shared sin-fract noise used by flicker/cutscene/blackout jitter), and `srand` (seeded RNG used only by map gen, so layouts are reproducible).
- **`settings.js`** — `SETTINGS_KEY` + `readSettings()`: the one reader of the persisted settings blob. Exists because scene.js needs the saved graphics quality at renderer construction (antialias is fixed at GL-context creation), long before ui.js evaluates.
- **`state.js`** — the flat mutable `STATE` object (player + progression for all levels; THE NEST adds `hasLantern`/`lanternOn`/`lanternCharge`/`cranking`, `clutchesLit`, `frenzyT`, `caveT0`), `KEYS` (raw input), the `monster` state object (level 0), and the `spider` state object (THE END + THE NEST — the same individual). Everything reads/mutates these shared objects.
- **`map.js`** — level-0 grid constants (`W`, `H`, `CELL`, `WALL_H`), random-walk carve in `genMap()`, `cellToWorld`/`worldToCell` conversions, `isWall`, `losCells` (line of sight), `bfsPath` (entity pathfinding). `CELL` is shared by both levels.
- **`textures.js`** — `makeCanvas` + procedural textures via 2D canvas: level-0 wall/carpet/stain/ceiling (only the ceiling carries a bump map), mold/drip decal growers, THE END's set (`texLib*`, woods, `makeCrackTexture`, `makeEndTextTexture`, `makePosterTexture`, `texBeige`, `makeKeyboardTexture`, `makeFloppyTexture`, and THE END's graphics-pass set: `makeWrapTexture` · `texTape` · `texCartPaint` · `texMannequin`), the shared electric-light pair (`makeTubeTexture` + `texGalv` — see below), THE NEST's rock/floor/dripstone + the silk family, and the shared spider chitin maps (`texSpiderAbd`/`texSpiderCarapace`/`texSpiderLimb`), THE NEST's `texEggSac`/`makeFlameTexture`/`texCocoon`. The two lathe-dressing maps have an ORIENTATION CONTRACT: u wraps the body, v runs front→rear, so a horizontal stroke becomes a RING — the carapace's striae must be drawn as VERTICAL strokes or the head reads as a cut tree stump, which is what the first pass shipped. All the chitin maps are kept near-neutral: warm browns times the lantern's orange multiply out to BRONZE, and the spider looked cast rather than grown. `texCaveRock` is 512² because the walls are UV'd at 4m/tile — at 256 a facet you stand beside was a smooth gradient. It is built from multi-scale blotching plus SHORT angular joints drawn wrapped: never long smooth curves, which tile into visible worms crawling across every wall. `texCaveFloor` follows the same lesson at ground level — sediment lobes, runoff channels, drying cracks and proud stones with lit crowns, all MID-scale, because the old floor was 9000 sub-pixel dots that averaged to flat brown and gave the bump map nothing to bite. `texLibCarpet` learned it a third time: at 4m/tile the pile is sub-pixel, so 26 000 dots averaged straight back to the flat field they started from — what reads is BERBER FLECKS (rust/ochre/bone fibre), the loop rows, and the traffic worn into it, over a matching `texLibCarpetBump`. Its tone-on-tone lattice is deliberately near-invisible: at any real contrast it stops being a weave and becomes grout, and the floor turns to ceramic tile. LEVEL 0's tiling surfaces are back to their ORIGINALS, and the reason is a Key convention below: `texWall` is 256² of eight flat stripes at 64 px/m, `texCarpet` 512² over an 8m tile, `texStains` and `texCeilStains` 512² each. The 4×-resolution rebuild of the wall shipped as veneered plywood (half-metre drop seams read as panel lines, ±8 per channel of batch drift made four drops read as four PANELS, a full-width "paper weave" rule every 4px was 256 courses of machined lumber, and sixty `fillRect` grime blocks along the skirting put four visible corners on every mark); the carpet went the whole way to CERAMIC TILE (a half-metre tone-on-tone lattice is grout, drawn in the diffuse map *and* embossed in the bump map in both axes; a 4px tuft grid is a 3cm mosaic; a 198-grey fleck is terrazzo aggregate); and the 1024² stain overlays grew CROP CIRCLES, because at ~40 px/m the big field stamps run three or four metres across and a closed tide line round one of those is a ring on the floor you can see from the far end of the corridor. The carpet keeps exactly two things the original lacked: a 54-stamp BROAD MOTTLE laid down first, and yarn flecked across five tones instead of flipped between two — an even speckle at one alpha over one flat colour is a product swatch, and what makes a floor look LAID is that it is blotchy at the metre scale. Both fleck extremes are held well off black and white: at 64 px/m a 2px dab is 3cm of floor, and a hard dark speck that size is not a fibre, it is GRIT, and the whole floor goes over to wet sand.
  `texCeil`/`texCeilBump` are the one part of that pass that stayed, and they are 1024² over the 4m repeat (256 px/m, 1m tiles, sixteen to a canvas), because a drop ceiling needs three things a drawn grid can't give — the grid is HARDWARE (a metal cap with the tile edge falling away into shadow either side; that reveal is the entire illusion of depth), every tile is a different tone, and the FACE IS MINERAL FIBRE. That face is `ceilFace`, and both maps are drawn from ONE per-tile SEEDED sequence: they used to roll their own randoms, so the relief and the print described two different tiles — a slit shaded dark in one place and a groove pressed in another — which is most of why the face read as smooth plaster with scratches on it, and plaster does not take the brown tide rings and mold this level hangs on it. Every random in there is drawn UNCONDITIONALLY and up front or the two passes diverge. What reads is a needle-PERFORATION field (2px, a third of them carrying the burr the needle pushed up — at 256 px/m a real 1.5mm hole is under half a pixel, so these are the pattern, not the holes), lumpy WOOL under it, short FIBRE at every angle, and FISSURES running with each tile's own grain. A FISSURE IS A SLIT, NOT A CRACK: 56 a tile at 40cm, kinked, dark, brightly lipped and over a 0.012 bump came out as BARK — the same cracked-eggshell failure as the version before it, only louder — so they run half as many, a third as long, barely kinked, with both the slit and its lip at the edge of visible, over 0.008.
  **The decals** (`makeMoldTextures`, `makeDripTextures`) are the originals too, at ~72 px/m, clamped and mipmap-free (their canvases aren't power-of-two, so WebGL1 would resize and blur them). They were regrown at 150/140 px/m with damp haloes, spore stipple, hyphal margins and mineral-edged rivulets — ~30MB of canvas against 7 — and all of it came back out: what belongs at that skirting is the small dark growth that was always there. THE GROWTH LOGIC WAS NEVER THE PROBLEM and has never been touched in either direction; the shapes, sizes, counts and placement are the original's. `makeFloppyTexture` is 256² with `anisotropy` 8 — a disk lies flat and is read at a grazing angle, the worst case for an isotropic mip chain — and its `top` UV band is mapped the RIGHT WAY UP (v0 < v1). Reversing v to drag the printed shutter onto the end the steel shutter sits on works on the block layout and is fatal to the print: it mirrors the canvas, so every glyph came out upside-down while still running left-to-right, invisible only because 128² had made the lettering an illegible smear. The end-for-end problem is fixed in `makeDisc` instead, by putting the steel on the end the print gives it. `makeTubeTexture(warm)` is THE FILAMENT — the one asset every electric light in the game shares (level-0 troffers and THE END's strips): the canvas HEIGHT is the tube's length (CylinderGeometry's v runs end-to-end), which is what makes END BLACKENING possible, and without the mercury baked onto the glass at the electrodes a tube is just a glowing stick. It must stay bright on average — lights.js drives `tubeMat.color` every frame and this map multiplies it. `texGalv` is the galvanized sheet every fixture shell wears, mapped at a fixed world scale so a 2.2m reflector spine and a 0.09m end cap carry the same steel. `texReflector` is the troffer's painted-steel backplate: like the filament it MULTIPLIES a colour lights.js drives every frame, so it must stay bright on average, and what it buys is SHAPE — a MeshBasic backplate is one flat value, so a trough pressed out of it would look identical to a flat sheet, and the two bright lanes under the lamps (on the THIRDS, v 1/3 and 2/3), the shadow the side walls throw, the dust and the grime runs all have to be printed. It had DEAD FLIES printed on it, legs and all, and from below a scatter of small dark bodies in a lit tray is COCKROACHES — there is no such thing anywhere in this world; what is left is three or four wobbling rust blobs at 0.05–0.12 alpha. `texLouvre` wraps the guard grid's ROD, so u runs AROUND the bar rather than down a face: u=0.25 is the top, facing the lamps 90mm above it, u=0.75 the underside you stand below, and a cosine keeps both canvas edges at the same mid value so the wrap is seamless. Get that inconsistent between the two rod families and half the grid is lit from underneath. `scaleBoxUV` takes an optional `skip` face list for boxes with one FITTED face (a printed label) that must keep its 0–1 mapping while the rest tiles.
- **`scene.js`** — Three.js scene/camera/renderer, the point-light pool, and `buildLevel()` (level 0 geometry; populates the exported `lights` array). Objects present at module init are tagged `userData.persist`; `clearLevelScene()` removes everything else (the level-change teardown) and resets `lights`/`wallMeshes`/`wallDecals`. `setLevelEnvironment(level)` swaps fog/ambient profiles. `makeLightRecord()` is the single fixture-record factory: every light in the game (level-0 troffer or library hanging strip) is the same self-contained filament asset driven by lights.js — builders only choose the knobs (`bright`/`dimDen` set how yellow a panel idles; `warm`, `flickery`, `fixY`, `wakeAt`). `buildLevel()` uses raw box UVs on the walls and the carpet's original 8m tile; the CEILING is the only level-0 surface still carrying a bump map (0.008, down from 0.012 — with the tile face carrying real fibre relief now, the old scale turned its fissures into raised veins). **The ceiling is not a plane.** `ceilingGeometry(SZ,openings)` emits it as a quad grid — one quad a cell, and four border strips around a cut opening in the cells that carry a fixture — with UVs straight from world position so the tiling runs across the joins exactly as the single plane's did, still one draw call. The winding is load-bearing: `(B−A)×(C−A)` has to come out (0,−1,0) or the field faces up into the void and the level has no ceiling at all. The openings exist because the troffer is RECESSED half its depth (`RISE`) into the ceiling: everything above `WALL_H` — the pan, the reflector, both lamps — is otherwise occluded by the very plane it is set into, and the fixture comes out as a dark slot with a grid over it. The fixture SLOTS are therefore chosen at the top of the build, before the ceiling exists, and the ceiling-stain overlay takes the same openings or it hangs across every fixture's mouth as a translucent film. `makeTroffer()` builds the troffer from module-level `markShared`'d geometry (the mirror of library.js's `makeFixture` for the hanging strips) — only the per-fixture glow/tube/rod materials are created per build. THE GRID UNDER THE LAMPS IS ROUND BAR: 16mm rods, 12×6 cells at a 0.22m pitch, and the two families sit one bar-diameter apart in y because a welded grid is welded — at the same height they interpenetrate and every crossing eats a bite out of the run behind it, which came out as visibly DASHED long runs. It was twenty single quads wearing a printed top-to-bottom gradient, i.e. a real egg-crate louvre blade, and 1.4mm of steel seen edge-on is NOTHING: the grid vanished from the one place everybody looks at a ceiling light from, straight up at it, and reappeared as graph paper from anywhere else. All twenty rods still merge to one draw. The housing is `bakeParts`-merged from a pan, four walls, the rim the grid sits in and the TRIM FLANGE (it was six draws — a box with a six-material array). That flange is a RING, never a plate — a plate closes the opening it is trimming: it stays down at the ceiling line while the rest of the fixture rides up, its top sits 1.5mm PROUD of the ceiling plane so the two intersect rather than fight for the same depth, and it is the only thing hiding the 6mm clearance (`OPEN_C`) the opening is cut with. The lampholders are ivory, merged, and are what says the tube is seated in something rather than floating in a box; the two tubes sit on the THIRDS (`TUBE_Z=FD/6`) and merge into one buffer — there was a ballast wireway boxed down the spine between them, which from below is a beam bolted across the middle of the light. 5 draws a fixture, down from 10. The exported `tubeTex`/`warmTubeTex` are the shared filament maps both levels' tubes wear.
- **`props.js`** — collectible/breaker/exit-elevator builders, `placeProps()`, the `interactables` array (+ `clearInteractables`/`addInteractable` for level changes), `updateProps()` idle animation. The three things you are sent to find are real objects: the almond water is a lathe-turned PROFILE (heel, straight side, shoulder, neck, lip — the whole difference between a bottle and a tin can), closed at radius 0 on the base and left open at the lip where the cap covers it, with the liquid as its own inner lathe filled to just under the shoulder (a transparent bottle you can't see a level in is a solid) and a printed label; the fuse is a glazed ceramic cartridge with brass ferrules and FLAT brass blades (flat is the tell that it's a contact and not a peg), and its origin must stay at the base with height ~0.3 because the cutscene flies that exact group into the slot; the breaker is a load centre — recessed cabinet, folded flange, knuckle hinges, printed maker's plate and circuit directory, dead breakers flanking the one live slot. `makeBreaker` keeps a hard contract with cutscene.js: `doorPivot` (a Group at (−0.45,0,0.2) swung about y), `fuse` (a Group whose every material is faded up from 0), `lamp` (a single mesh whose own material is recoloured) and `lever` (a single mesh moved in y from −0.1 to +0.1). Prop canvases are module-level and `markShared`'d — `placeProps` runs again on every respawn, and teardown disposes anything unmarked, so a rebuilt level would come back wearing dead textures. `makeElevator(p,facing,opts)` takes `{wallH, wallMat}` so THE END reuses it for the crashed arrival cab; `opts.uvTile` maps its odd-sized flank/header boxes at a fixed world scale (THE END), and without it they take raw box UVs like every other wall on level 0. The elevator is carved into its wall cell (the wall box mesh is removed and rebuilt as flanks + header around a recessed cab; the grid cell stays solid for collision). **THE CAB IS REAL HARDWARE**, and the whole rebuild is paid for by per-material merge buckets (`put`/`flushBuckets`): it has five times the parts the six-box version had and costs FEWER draws. Its panel seams and kick plate used to be PRINTED into a cab-wall canvas that then tiled onto boxes of four different sizes — a unique feature in a tiling map, level 0's wallpaper mistake exactly — so the seams are raised boards between stiles now and `texElevSteel` carries only the FINISH (one bright near-neutral brushed map under four tints: bright doors/jambs, mid lining, dark trim, a smoked panel held off both extremes because at a near-black base under shininess 110 it flipped between a doorway-shaped black rectangle and a white blob). What is in there: a grooved SILL whose front groove `zg1` is the same number the door leaves' gibs ride at; leaves that are formed panels (face sheet, folded returns top and bottom, a dark astragal down the meeting edge with a rubber safety shoe, kick plates on both faces); a luminous ceiling with a ROUND-BAR egg-crate (the troffer's lesson — 1.5mm of blade seen edge-on is nothing, and straight up is the one angle anyone looks at a cab ceiling from); an INSPECTION HATCH whose trim is BRIGHT, because 18mm of dark trim on a dark ceiling is invisible; a handrail on real brackets; return-air grilles in the KICK and the COVE, the only two bands of the back wall that are not panelled; and a car operating panel, a hall station and a jamb plate whose prints are ENGRAVING (a dark cut with a bright lip on a transparent ground, so the steel shows through). `opts.wrecked` is what makes THE END's cab the one the brakes failed on rather than a second working elevator — the hatch forced open and hanging INTO the car (down, not up: swung up it drives 0.5m of lid through the slab it is hinged to) over a black aperture plane, two bars gone from the egg-crate and a third bent, the back panel broken, one leaf rolled out of its track about z (never about x — the cutscene owns `.position.x` on both leaves and any damage living there is wiped the first time the doors move). **EVERY DIMENSION IN THE CAB DERIVES FROM `ELEV`** (`OPEN_W` 2.2 · `OPEN_H` 2.73 · `DEPTH` 2.6), and that is what makes a resize a three-line change instead of a hunt through eighty literals. The parts that had to be solved rather than written down, because a hardcoded copy of them silently detached from the cab the first time it grew: the back wall's three boards (`BPW`/`BPX` — solved from the lining so the corner margin and the gaps hold at any width; the capacity plate and the return-air grilles ride `BPX`, or the board walks out from under them), the egg-crate's cross-bar pitch (`CRX` — a fixed 0.295 shunts the whole family to one side), the handrail's bracket spread and its side runs (off `IN`, not 0.865/0.905, or the rail floats in the middle of a wider car), and the leaves. `ELEV.LEAF_W`/`LEAF_X`/`TRAVEL` are the leaf's own geometry and cutscene.js reads them rather than keeping its own ∓0.515/1.0. `TRAVEL` is deliberately CAPPED at `CELL/2−LEAF_W`: a full retraction wants a pocket as wide as a leaf, and at a 2.2m opening in a 4m cell the flank is only 0.9m — uncapped, each leaf drives 0.23m of door out through the far side of the wall into whatever is standing there, so it stops at the cell edge and shows 0.23m of steel in the jamb instead, which is what a real lift does anyway. `HALL.x` is measured off the opening (`OPEN_W/2+0.28`) for the same reason: the jamb runs to `OPEN_W/2+0.15`, and a flat 1.222 put the plate's edge exactly on that line, so the first widening slid a third of the hall station under the jamb's steel. `COP.y0` is 1.06, not 0.90 — the handrail runs the side wall at 0.95 and its brackets reach 0.99, and the plate used to start 0.14m below that, with the alarm button and the IN CASE OF FIRE legend behind a steel tube. The whole table (buttons, print, and the floor indicator, which reads `y0+h`) lifts on that one number. The cutscene contract is unchanged and load-bearing: `doorL`/`doorR` (Groups now, closed at ∓`ELEV.LEAF_X`, `.position.x` driven), `cabLight`/`cabLightMat`, `emergMat`/`emerg` (`emerg` MUST stay a DIRECT child of the group — the ride cutscene copies its `.position` straight into a PointLight in the group's frame), `panelBtns` (4), `drawFloor`, `dispLocal`, `btnMat`/`btnLocal` (the DOWN call button), `sign`, plus `hallLamps` which the ding lights.
- **`library.js`** — THE END: `grid2` gen (one vast room; perimeter walls, shelf runs that converge/anchor into walls, table islands, the central 3-cell desk), connectivity repair, type-aware queries (`libCollide` — tables passable only while crouched, plus circle obstacles in `LIB.obstacles` for chairs/lecterns/ladders; `losCells2` — shelves block sight, tables/desk don't; best-effort `bfsPath2` that routes to the nearest standable cell when the target is unreachable; `cellAt` for the spider's leg-terrain probe), `buildLibrary()` (geometry — wall boxes get world-scaled UVs via `scaleBoxUV` so the tileable plaster never distorts; hanging fixtures pushed into `lights`; furniture, readable-nonsense posters, cracks, wall texts, vintage PCs, 16–22 floppy disks, the terminal). **THE HANG** (`makeFramedArt`): a picture on a wall is not an image, it is a MOULDING with an image inside it, and the three things that say so are all things a print cannot do — a profile that steps FORWARD as it steps OUT (so the top member throws a shadow line and the outer bead catches the strips first), a mat with a real BEVEL cut through it (a strip turned 45° at the sight edge; it reads as a different tone purely because it faces somewhere else), and GLASS. All geometry, and affordable because every piece's frame/mat/backing/pane is merged ACROSS the room by material at the end of the hang: ~34 pictures cost ~40 draws where 14 flat planes cost 14 (only the art plates stay individual — each is its own canvas). Oval mats are a `ShapeGeometry` with an elliptical hole, because an oval cannot be made of boxes and the oval IS the point of it. Pieces go up in CLUSTERS laid out with a running CURSOR, not on a fixed pitch — a salon hang leaves a hand's width between frames, and stepping by a constant ~1.5m scattered five pictures over five metres of wall, which is not a cluster, it is five pictures. The cluster's overlap check must use a margin SMALLER than the gap the cursor leaves (0.045 against 0.10–0.19): at the old 0.22 it rejected every second piece in every cluster and quietly turned a 34-picture hang into a 10-picture one. A wall face is only dressable if the cell in FRONT of it is open — a shelf run that anchors into the perimeter fills that cell, and a 70mm-deep frame hung there grows out through the end of the stack. Cracked glass runs at a THIRD of the opening and off-centre: `makeCrackTexture` grows a crack for a 3m wall, and stretched over a whole pane it is one black branch the size of the picture. **THE FLOOR POPULATION** is joinery's opposite number and had to learn the same lesson three ways. The DISPLAY FORMS were a cylinder with a sphere on it and a stick for an arm — a snowman on a pole: a dress form is a PROFILE (hip, waist, bust, the shoulder slope, the sharp cut at the neck) and turning it is the whole difference, exactly as it was for the almond water bottle. Every lathe closes at both poles; the SHOULDER is the load-bearing part of `FORM_PROFILE`, because a radius running smoothly down from the chest to the neck is a chess piece — a form holds its width to t≈0.86 and then falls off a cliff, and that cliff is the shoulder line. The arms are jointed (shoulder ball, elbow, wrist peg), the nose is SMALL and sunk in (at 22×55mm standing clear it was a beak), and the shell is MATT (at the old specular a warm light turned every form in the room into polished brass). `texMannequin` is fitted, u around and v base→neck, so the two mould parting seams are VERTICAL strokes at u=0 and u=0.5. Packaging is decided FIRST because it constrains the head: a form still sealed in film cannot have its head lying on the floor outside the bag. **EVERY VOLUME IN THE BUILDING IS SIZED THROUGH `BOOK_S`** (1.21) — the closed designs, the open book (which carries the same base numbers rather than its own literals, or it drifts away from the volumes lying open beside it) and the load on every trolley. It cannot go much higher: the tightest clearance in the room is the 0.375m between shelf boards, and at 1.21 the tallest design stands 0.363 (measured worst case in a built room: 6.5mm of daylight over 846 shelved books). The trolley carries its own `CART_S` (1.10) and must move WITH it — its decks are 0.36 apart, i.e. 0.34 of clear height, which a 0.363 volume goes straight through. Rather than re-type thirty literals the whole structure is scaled at the merge (positions AND geometry, castor groups via their own transform), and the load is placed in the scaled frame; the books are already at `BOOK_S` and must NOT be scaled a second time, which is why they go on after the merge, unscaled. `CART_R` is its keep-out and rides `CART_S` too. The RETURNS TROLLEY was eleven bare boxes in one flat grey with four discs lying on their sides for castors; a book truck is SHEET STEEL, so every edge is folded (decks are plates with a hemmed lip turned down on both long edges, ends are pressed panels with a rib and a swage, corners take rubber bumpers, the handle is a bent tube with real ELBOWS, each castor is plate + swivel + fork + a rubber tyre on a hub) — three merged draws where the old one cost eleven before a book went on it. Its enamel is DESATURATED on purpose: a warm saturated tint over a bright map turned a hemmed steel deck into an orange plank, and the whole truck read as joinery in a room already made of joinery.
EVERY WOODEN THING IS JOINERY, MERGED BY MATERIAL: shelf runs get a plinth, a crown rail and a lipped front edge on every board (the shadow line under that lip is most of what tells your eye a shelf is a shelf) in 3 draws where five bare slabs cost ten; tables get a plank top with real seams, a bullnose band, a deep apron and tapering legs — and NO stretchers, because a table cell is passable to a crouched player and a bar at shin height is a bar you crawl through while hiding under the only cover in the room; the desk is panelled between stiles with a counter, nosing and transaction ledge instead of one 11m untextured slab. Plinths and crowns are held FLUSH with the collision slab (`SHELF_D/2+0.02`) — anything proud of that is something you walk your face through. THE GRAIN HAS A DIRECTION: both wood canvases are drawn grain-down-the-image, right for a stile and wrong for anything lying along its length, so horizontal members use a rotated CLONE (`shelfMatH`/`deskMatH`) — free, and without it every board in the building reads as painted MDF. `taperBox` narrows a box toward one end (legs, the CRT). `makeFixture` is a REFLECTOR now, not a lit slab with two sticks under it: a pressed spine, two wings splayed down and out (placed by their EDGES — a plate's local +z under a rotation θ about x points at (y=−sinθ, z=cosθ), so hinging one at the spine's z edge lands the outer edge exactly where the trough should open), end caps, sockets over the glass ends, a guard cage, and a drop with an eye and a ceiling plate. All of it is galvanized sheet so it merges to ONE mesh; only the backplate and the tubes stay separate, because lights.js repaints their materials every frame — 3 draws a fixture, half what the flat slab cost. `makeVintagePC` tapers the tube to its neck, recesses the glass behind a real bezel with a paraboloid bulge, and prints the keyfield rather than building 90 keycaps — 4 draws, down from 9; the screen canvas and the drive LED stay separate meshes because cutscenes write their materials. BOTH SETS OF VENTS ARE SEATED ON SURFACES DERIVED FROM THE GEOMETRY, not placed by arithmetic that never meets one. The crown SLOPES — `taperBox` pinches the CRT's −z end, so the top face runs from (+D/2, +H/2) down to (−D/2, +H/2·k) and each vent is seated on `crownY(z)`; a ladder of plates climbing in y at one fixed z put all six of them in open air above the monitor, the highest 0.1m clear of the glass, and a 0.34m board floating over a CRT is the largest unattached thing in the room. - **`player.js`** — `updatePlayer()`: movement, sprint/stamina, jump physics, AABB collision (level-aware: `libCollide` in THE END, `caveCollide` in THE NEST; uncrouching is blocked under a tabletop or a squeeze), camera/head-bob, the post-drop micro screen shake (`STATE.shakeAmp`), footsteps. Ground height is level-aware: THE END's stair (`libGroundY`/`shaftClamp`) descends, THE NEST's chimney (`caveGroundY`/`caveShaftClamp`) ascends, the stream is a −0.14m wade and the chasm returns −999. Cave footsteps pick a voice per `surfaceAt` (stone/water/scree); cranking caps speed at 2.4 m/s; wading drags −20%. Once the breaker is fixed (`STATE.powerOn`, level 0 only), adrenaline: bottomless stamina shown as a blue ADRENALINE bar, +20% sprint speed (9.6 m/s).
- **`lights.js`** — `updateLights()`: event-driven flicker bursts (proximity of the level's hunter triggers them — flicker is the radar on every floor; level 0 keys on the monster, 1–2 on the spider), light-pool binding (per-fixture `fixY` height), positional buzz binding (records with `buzz:false` — the fungus — stay silent), the level-0 troffer's `louvMat` emissive (the guard rods hang 90mm under a burning tube so they are lit BY it — the tubes are unlit MeshBasic and cast nothing, and the pool light standing in for the fixture sits BELOW the rods, so real shading would light their undersides, which is backwards; an undriven grid also hangs bright under a dead lamp), THE END's wake-wave gate (`STATE.libWakeT`), the 75%-dim + warm shift (`STATE.libDim`), blackouts (`STATE.libBlackout`), and THE NEST's `cold` records (per-colony `tint` drives the emissive color — components may exceed 1 because the fungus emissive MAP averages under white — and `poolCol` colors the bound pool light; no warmth pipeline, no ballast ticks; `mul2` applies the per-region fungus die-back).
- **`interact.js`** — `updateFocus()` (what [E] targets within 2.7m; labels may be functions), `tryInteract()` (objective progression for all levels; disc pickups call `spiderHearDisc`; the corpse yields lantern + journal), and `updateInteractHold()` (THE NEST's 3s stationary ignite channel — striker ticks, a live percentage in the prompt, `igniteClutch` on completion).
- **`cutscene.js`** — `CINE` state + the scripted cinematics (the dig FX: THREE puff maps rather than one, because a single sprite map repeated 150 times reads as 150 copies of the same blob however you tint it, each built from soft lumps AND a coarse grain pass because a smooth radial falloff is fog while dust has dirty edges; four emitters — a gusting `billow` churn, the ground shroud, a long-lived high VEIL that gives the aerial camera something to look down THROUGH, and debris including flat carpet shreds that flutter; sprites are UNLIT, so the palette carries two near-black entries or the cloud turns into a cotton ball hanging over the desk): the breaker fuse animation (entity rushes the panel at chase speed, freezes at a 30m ring until control returns), the exit-elevator escape/brake-failure ride (its end calls `enterTheEnd()` — the crash IS the level transition), THE END's intro (waking in the wrecked cab, doors grinding open in two tries, the fixture wake-wave, title card), the terminal ending (boot → "THE END" → static → the camera cranes up to an aerial seat chosen at runtime for clearance from the random fixture canopy → the spider sprints in and digs itself under behind the desk inside a brown/blue dust shroud, `revealHole()` swapping the carpet plug for the open shaft at peak dust → crane back into the player's eyes while the terminal's CRT burns red with "I WARNED YOU" (`screen.warn`) → control returns with the ENTER THE HOLE objective). The last word is not a word: `screen.warn(alpha,t)` draws a CRYING FACE on the coarsest grid the glass holds (24×18 cells of 8px, every feature stamped as a mirrored pair about the seam between columns 11 and 12 so it cannot come out lopsided), and `LIB.weeping` keeps the tears running in `updateLibrary` long after the cutscene hands you back — a tear frozen halfway down the glass is a picture, not a face. EVERY FEATURE HAS TO CLEAR THE OUTLINE: the head is only ~7 cells of radius under a one-cell ring, the first pass put an eyelid straight through it, and under the tube's bloom the whole top half fused into one lump with two dark holes in it. And THE STREAK IS THE WHOLE THING — three loose drops under an eye read as noise on a CRT; a standing wet line down each cheek is what makes the face crying rather than merely sad, and the descent's last beat (`startDescentEnd` — the stairs themselves are walkable; main.js fires this only once the player has walked below `STATE.y<−8.5`, where the depth fog has already taken most vision: the view drifts on downward while the black closes, stone footsteps continue a few seconds, then hands off to `enterTheNest()` under the same black — the descent IS the level transition). THE NEST adds its own intro (`startNestIntro` — waking at the stair's foot, craning back up at the silk-wrapped way you came, title card "THE NEST / level 8, wrong side out") and its ending (`startAscentEnd` — main.js fires it only once the player has CLIMBED the open fissure's chimney above `STATE.y>9`: the view spirals on upward while a cold pale — not black — closes in, stone steps and updraft wind carry on, then `win()`). While `CINE.active`, main.js skips `updatePlayer`/`updateFocus` and the cutscene owns the camera; `window.NOCLIP_DEBUG` (main.js) exposes hooks for smoke tests, and hidden debug chords exist: triple-[6] warps to the level-0 endgame, triple-[7] drops into THE END (or, already there, pockets every remaining disk), triple-[8] warps to the terminal with every disk pocketed, triple-[9] drops into THE NEST with the lantern (or, already there, burns the brood down to one and stands you at the survivor).
- **`lifecycle.js`** — `startGame`, `enterTheEnd` (teardown + library build + intro), `enterTheNest` (teardown + cave build + intro; swaps the keys hint for the lantern controls), `respawn` (level-aware: THE END respawns at the wreck keeping disks; THE NEST respawns at the dead stair keeping the lantern and every burn), `die`/`win` (level-aware copy + stats — and in THE NEST both call `hushCave()` + `silenceHatchlings()`, because main.js stops calling `updateCave`/`updateHatchlings` the instant you die and every loop the level is holding open would otherwise freeze at its last gain and drone under the death screen), debug warps.
- **`ui.js`** — DOM refs (`ui`), `toast`, objectives HUD (level-aware), overlay/pause logic, pointer lock, settings persistence (key + reader live in `settings.js`), mixer wiring.
- **`input.js`** — keyboard/mouse/pointer-lock listeners (side-effect module).
- **`main.js`** — imports everything and runs the `requestAnimationFrame` loop; dispatches `updateMonster` vs `updateSpider`+`updateLibrary` vs `updateSpiderCave`+`updateHatchlings`+`updateCave` on `STATE.level`; `updateLantern` and the descent/ascent cinematic triggers run here too.

THREE is a global (classic CDN `<script>` loads before the module graph) — modules do not import it.

There are intentional function-level circular imports (`monster ↔ lifecycle`, `ui ↔ lifecycle`, `cutscene ↔ lifecycle`, `spider ↔ lifecycle`, `library → ui → lifecycle → library`, `cave ↔ lifecycle`, `cave → ui → lifecycle → cave`, `spider → cave`/`spider → hatchling` one-way); they are safe because nothing in the cycle is called during module evaluation. Don't add top-level calls across these boundaries.

## Key conventions

- The map coordinate system uses `cellToWorld` / `worldToCell` (level 0), `cellToWorld2` / `worldToCell2` (THE END) and `cellToWorld3` / `worldToCell3` (THE NEST) to convert between grid cells (integers) and Three.js world space (meters). `CELL` (4m) is shared by all three.
- `MeshPhongMaterial` is used deliberately over `MeshLambertMaterial` on large floor/ceiling planes — Lambert is per-vertex in Three.js r128, which produces all-or-nothing lighting on geometry with only corner vertices.
- **Nothing UNIQUE may live in a tiling map.** A one-off feature drawn into a texture that repeats becomes that feature repeating on the tile pitch, which reads louder than whatever it bought — a single lifted wallpaper seam turned into an identical lifted seam every 2m down every corridor in level 0. One-off damage goes on a decal (the mold/drip system is exactly that); a tiling map may only carry what is true everywhere.
- **A texture's resolution is px/m, not canvas size**, and the two are only related through the UV rate. Every generator in this codebase has been rewritten at least once for the same reason: features drawn below the size the eye resolves at the distance you view them from average straight back out to the flat field they started on. Check px/m before adding detail.
- **LEVEL 0's tiling surfaces are deliberately plain, and the restraint IS the atmosphere.** The wall, the carpet and both stain overlays were rebuilt at 4× resolution with drops, seams, batch tones, berber flecks, tide rings, bump maps and printed grime. Every single one of those upgrades shipped as a defect — veneered plywood, ceramic tile, crop circles on the floor — and all of them have been reverted to the originals. A surface you walk past for twenty minutes at a 4m repeat cannot carry a FEATURE: anything nameable on it becomes the thing you see, everywhere, at once. Detail on this floor goes on the decals (unique per instance) and on objects (props, fixtures), never into the tiling maps. The ceiling is the exception that proves the rule — what it got was not features but MATERIAL (`ceilFace`).
- **Nothing organic may have a straight edge.** Damp, grime, mold, spills and stains drawn as `fillRect` put four visible corners on every mark — a wall covered in faint hard-edged rectangles stops being stained and becomes veneer with printing on it, which is exactly how level 0's rebuilt wallpaper shipped. Use gradients or paths. The same applies at a decal's own border: the instant anything inside it still has alpha at the canvas edge you see the decal's RECTANGLE, however soft the art is (THE NEST's `silkFeather` is the surviving example of the fix).
- **ALPHA IS THREAD-SHAPED, and it is not only silk.** THE END's plastic wrap was a box at 0.18 opacity wearing a flat blue-grey — a CUBE OF FOG, a solid you can see a little way into, with six hard corners and not one fold. What makes film read as film is never the tint: it is the CREASES, so the map carries strokes and nothing else. The first rewrite still laid down nine broad soft blooms "where the sheet lies doubled", and a 60px radial gradient at 0.12 alpha is not a fold, it is a milky PATCH — it came out as a glowing oval floating over the object inside. Same rule, same reason, as THE NEST's `silkFeather`: no broad translucent fills anywhere.
- **A CRUMPLED SURFACE IS FACETS, and `flatShading` is worth as much as the geometry.** A smooth-shaded shell of a crumpled silhouette is a BELL JAR — which is exactly what the wrap came out as until its material went flat-shaded and its mesh went COARSE (20×14, not 32×20: with flat shading the panel count IS the fold count). The folds that matter are the LOW harmonics, because what reads as crumpled is the SILHOUETTE — amplitude spent on k=5 and 7 is surface ripple you cannot see against the room. And a fold field that barely drifts with height runs every ridge the full height of the bag and comes out FLUTED, like a column.
- **TWO PASSES DRESSING THE SAME WALL MUST READ ONE LEDGER.** THE END hangs its walls in four passes — texts, posters, the picture hang, cracks — and only the hang tracked what it had placed. The other three took a face off a cycling cursor and stamped themselves on it blind, so no pass could see another's work; and once the four of them between them wanted more faces than the room had, the cursor WRAPPED and the last pass (the cracks, which is why the branching crack decal was the symptom) came down on top of pictures already hanging. They all book their rectangle in `dressed` now and all check it first, and `place()` walks the face list for a free spot instead of taking the next face blind. The elevator books a rectangle too: the south wall already skips the cells either side of the doorway, but a keep-out written in WORLD space is the one a pass added later cannot fail to see.
- **A SPACING CHECK MUST NOT BE WIDER THAN THE SPACING IT VALIDATES.** The library's picture hang lays its clusters out with a 0.10–0.19m gap and then rejected any piece within 0.22m of a neighbour — so every second picture in every cluster failed, silently, and a 34-piece hang shipped as a 10-piece one. Nothing about it looked broken; only counting the placed objects found it.
- **PRINT AND HARDWARE READ ONE TABLE.** `COP` and `HALL` in props.js are shared layout objects: the faceplate box, the engraved canvas and the button meshes all derive from the same numbers, so an engraved numeral cannot drift off the button it belongs to and an arrow cannot end up behind one. Same rule that put the vintage PC's vents back onto the surfaces they sit on.
- **A REGULAR GRID DRAWN INTO A FLOOR OR WALL MAP IS TILE.** It has happened three times — the library's carpet, level 0's carpet (in the diffuse map *and* embossed in the bump map), and level 0's wall. A lattice at any real contrast is grout; a tuft grid at 128 px/m is a 3cm mosaic; a full-width rule every 4px is lumber. Textiles are a SCATTER with a broad metre-scale mottle under them, and paper is nearly featureless.
- **`mergeStatic` ends in `freezeStatic`**, so a `.position.set` on its result writes a matrix that is never recomposed and the mesh silently renders at its parent's origin. Bake placement into the source meshes before merging, or re-enable `matrixAutoUpdate` deliberately (spider.js's abdomen does the latter).
- Light pool pattern: `LIGHT_POOL_N` point lights are reused each frame, bound to the nearest fixtures within `LIGHT_BIND_RADIUS`, instead of one light per fixture. All levels' fixtures share the same `lights`-record shape (library records add `fixY`/`wakeAt`; cave records add `cold`/`buzz:false`/`mul2`/`region`). `cold` records KEEP the idle breathe (it is the intended slow pulse) but never enter a flicker BURST: `canBurst` is gated on `!L.cold`. Strobing is a failing ballast, and a mushroom has not got one — the bursts were inherited from the electric floors and read as wrong on a plant. Fungus reacts only through `mul2`, the region die-back when a brood burns.
- Never change the scene's light COUNT at runtime — three.js r128 keys shader programs on it and recompiles everything in one frame (a hard hitch). Reveal-later lights (the library's hole, the cave's fissure and clutch fires, the lantern) are all created up front at intensity 0 and pre-warmed with `renderer.compile`.
- Exported `let` bindings (`grid`, `grid2`, `grid3`, `exitDoor`, `lights`, `interactables`) are reassigned/mutated by their owning module; importers see live values but must not assign to them. All three grids are on `window.NOCLIP_DEBUG` (along with `W`/`H`/`CELL`/`cellToWorld`) for smoke tests.
- THE END's grid cell codes: 0 open · 1 wall · 2/3 shelf (along x/z) · 4 table · 5 desk. The spider treats every nonzero cell as solid; players pass type-4 cells only while crouched.
- THE NEST's grid cell codes: 0 open · 1 rock · 2 squeeze · 3 stream · 4 scree · 5 void · 6 bridge · 7 rubble. The matriarch treats 1/2/5/7 as solid; hatchlings pass squeezes (1/5/7 solid); players pass 2 only crouched and fall through 5.
