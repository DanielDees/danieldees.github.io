# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A first-person browser horror game — "NOCLIP: Escape the Backrooms" — vibe-coded with Claude Fable 5 / Claude Mythos 5. Vanilla JS ES modules with Three.js r128 from CDN; no build system, no package manager, no compilation, no image or audio assets (everything is procedurally generated).

Three levels as of v3.0.0: **LEVEL 0** (the yellow backrooms maze), **THE END** (the infinite library, entered when the exit elevator's brakes fail) and **THE NEST** (the fungus-lit cave below the library's dug stair). `STATE.level` (0/1/2) picks the active update path; the renderer, light pool, audio buses, interaction/focus, HUD and cutscene systems are shared across levels. Versioning: major = number of levels, minor = refinements to existing levels. Per-level lore documents (menu wiki entry + in-world found document, parse-ready) live in `lore/` — see `lore/README.md` for the format contract.

## Running locally

The game uses ES modules, so it must be served over HTTP (opening `index.html` via `file://` will not work):

```
npx serve .
# or
python -m http.server
```

GitHub Pages serves `index.html` at the repo root as the live site.

## Architecture

`index.html` is markup only (HUD + overlay screens); `css/main.css` holds all styling; game code lives in ES modules under `js/`, entry point `js/main.js`:

- **`utils.js`** — `$`, `clamp`, `lerp`, `angLerp`, `rand`, `hash` (the shared sin-fract noise used by flicker/cutscene/blackout jitter), and `srand` (seeded RNG used only by map gen, so layouts are reproducible).
- **`settings.js`** — `SETTINGS_KEY` + `readSettings()`: the one reader of the persisted settings blob. Exists because scene.js needs the saved graphics quality at renderer construction (antialias is fixed at GL-context creation), long before ui.js evaluates.
- **`state.js`** — the flat mutable `STATE` object (player + progression for all levels; THE NEST adds `hasLantern`/`lanternOn`/`lanternCharge`/`cranking`, `clutchesLit`, `frenzyT`, `caveT0`), `KEYS` (raw input), the `monster` state object (level 0), and the `spider` state object (THE END + THE NEST — the same individual). Everything reads/mutates these shared objects.
- **`map.js`** — level-0 grid constants (`W`, `H`, `CELL`, `WALL_H`), random-walk carve in `genMap()`, `cellToWorld`/`worldToCell` conversions, `isWall`, `losCells` (line of sight), `bfsPath` (entity pathfinding). `CELL` is shared by both levels.
- **`textures.js`** — `makeCanvas` + procedural textures via 2D canvas: level-0 wall/carpet/stain/ceiling (each with a matching bump map), mold/drip decal growers, THE END's set (`texLib*`, woods, `makeCrackTexture`, `makeEndTextTexture`, `makePosterTexture`, `texBeige`, `makeKeyboardTexture`, `makeFloppyTexture`), the shared electric-light pair (`makeTubeTexture` + `texGalv` — see below), THE NEST's rock/floor/dripstone + the silk family, and the shared spider chitin maps (`texSpiderAbd`/`texSpiderCarapace`/`texSpiderLimb`), THE NEST's `texEggSac`/`makeFlameTexture`/`texCocoon`. The two lathe-dressing maps have an ORIENTATION CONTRACT: u wraps the body, v runs front→rear, so a horizontal stroke becomes a RING — the carapace's striae must be drawn as VERTICAL strokes or the head reads as a cut tree stump, which is what the first pass shipped. All the chitin maps are kept near-neutral: warm browns times the lantern's orange multiply out to BRONZE, and the spider looked cast rather than grown. `texCaveRock` is 512² because the walls are UV'd at 4m/tile — at 256 a facet you stand beside was a smooth gradient. It is built from multi-scale blotching plus SHORT angular joints drawn wrapped: never long smooth curves, which tile into visible worms crawling across every wall. `texCaveFloor` follows the same lesson at ground level — sediment lobes, runoff channels, drying cracks and proud stones with lit crowns, all MID-scale, because the old floor was 9000 sub-pixel dots that averaged to flat brown and gave the bump map nothing to bite. `texLibCarpet` learned it a third time: at 4m/tile the pile is sub-pixel, so 26 000 dots averaged straight back to the flat field they started from — what reads is BERBER FLECKS (rust/ochre/bone fibre), the loop rows, and the traffic worn into it, over a matching `texLibCarpetBump`. Its tone-on-tone lattice is deliberately near-invisible: at any real contrast it stops being a weave and becomes grout, and the floor turns to ceramic tile. LEVEL 0 learned all of it a fourth time — every surface on that floor ran at 64 px/m, the lowest resolution in the game. `texWall` is 512×**1024**, and the shape of the canvas is the point: `paperBoxUV` tiles u at `PAPER_TILE` (2m, and `CELL/PAPER_TILE` must be a whole number so the drops run unbroken from one wall cell into the next) and spans the wall height exactly ONCE, which is ~256 px/m square in world space. **v is never tiled**: the vertical axis is COMPOSED — grime wicking out of the carpet, the rub of shoulders at hand height, dust toward the ceiling — and repeating it puts a skirting stripe every couple of metres up the wall. A box that doesn't start at the floor (the elevator's header) passes its own `y0` or that whole composition gets squashed into the strip above the doors. What makes wallpaper read as PAPERED is the DROPS: half-metre sheets, each with a hairline seam, a paler overlap edge and its own batch tone — and every one of those three is at the EDGE of visible, because the first pass at this resolution turned the wall into a stack of veneered boards. A drop seam at 0.30 alpha over a 2px groove is a dark panel line every half metre; ±8 per channel of batch drift makes four drops read as four PANELS; a full-width horizontal rule every 4px (drawn as a paper "weave") is machined lumber, 256 courses of it. The pattern is a 12.5cm satin stripe with a shallow valley between bands, both drawn as soft-edged GRADIENTS — a stripe filled as a rectangle has two hard verticals per band and sixteen of those per tile is a paling fence. `texCeil` is 1024² over the 4m repeat, and a drop ceiling needs three things a drawn grid can't give — the grid is HARDWARE (a metal cap with the tile edge falling away into shadow either side; that reveal is the entire illusion of depth), every tile is a different tone, and the face is fissured mineral fibre over a pinhole field, clipped per tile so nothing crawls across a bar. `texCarpet` is the same berber-fleck lesson in the backrooms' mustard, and it went the whole way to CERAMIC TILE before it came back: at 128 px/m a half-metre tone-on-tone lattice is grout (drawn in the diffuse map AND embossed in the bump map, in both axes), a 4px tuft grid is a 3cm mosaic six times any real loop gauge, and a fleck at 198 grey is the aggregate in terrazzo. There is now NO GRID ANYWHERE IN IT — the pile is a flat 34 000-dab scatter, the flecks stop well short of white, one roll seam runs in one axis only, and a 70-stamp BROAD MOTTLE goes down first, because an even speckle at even brightness is a product swatch and what makes a floor look laid is that it is blotchy at the metre scale. Three more things had to be walked back after seeing them in-engine and the reasons are in the comments: NOTHING UNIQUE MAY LIVE IN A TILING MAP (a lifted, curling seam was the best detail on the wall and became an identical lifted seam every 2m down every corridor — one-off damage belongs on a decal, which is what the mold/drip system already is); the wall's bump tooth read as popcorn stucco (at 256 px/m a 1px speck is 4mm of wall, and paper on plasterboard is nearly flat — only the joins aren't); and the ceiling's fissures over a hard bump read as cracked eggshell.
  **The decals** (`makeMoldTextures`, `makeDripTextures`) grow at 150 / 140 px/m — roughly 30MB of canvas across a level, up from 7 — and take mipmaps + anisotropy wherever the context is WebGL2 (`decalFilter`), because at this detail a mipmap-free decal CRAWLS at twenty metres. THE GROWTH LOGIC IS UNTOUCHED; what was missing is that a colony is not an outline. Four things turn a smudge into a growth: the wall behind it is WET and the damp reaches further than the mold; SPORE STIPPLE over the mass (painted `source-atop` so a flat scatter lands exactly on whatever shape the walk produced) is most of what your eye uses to tell mold from dirt; a growing MARGIN of fine hyphae — short, thin and faint, or they read as drawn grass; and colour that walks between black, olive and ochre instead of flipping between two constants. A drip is not a brown line either: it is a broad brown FIELD narrowing as the water runs out, built as one wobbling closed path so there is an outline to hang the dried tide edges on, with the rivulets living inside it and each one carrying a pale MINERAL margin either side of a dark channel.
  `soft(g,px,fn)` (canvas `filter:blur`) and `featherEdges(g,w,h,px,keep)` exist because of the same failure in two places. NOTHING ORGANIC HAS A STRAIGHT EDGE: damp, grime and old spills drawn as `fillRect` put four visible corners on every one, and NO DECAL MAY END ON A STRAIGHT LINE — the moment anything still has alpha at the canvas border you see the rectangle, which is what the mold's first damp halo did to every decal in the level. `keep` names the one edge that must stay solid (the seam the decal is butted against).
  `texStains` and `texCeilStains` are 1024² (≈40 / 32 px/m; they were 20 and 16). A spill wicks outward and dries from the edge in, so the value distribution of a plain radial gradient is backwards — what reads is an irregular outline with a dark tide ring on it. But ONLY THE SMALL ONES GET A RIM: at these rates the big field stamps run three or four metres across, and a closed tide line drawn round one of those is a crop circle on the floor. `makeFloppyTexture` is 256² with `anisotropy` 8 — a disk lies flat and is read at a grazing angle, the worst case for an isotropic mip chain — and its `top` UV band is mapped the RIGHT WAY UP (v0 < v1). Reversing v to drag the printed shutter onto the end the steel shutter sits on works on the block layout and is fatal to the print: it mirrors the canvas, so every glyph came out upside-down while still running left-to-right, invisible only because 128² had made the lettering an illegible smear. The end-for-end problem is fixed in `makeDisc` instead, by putting the steel on the end the print gives it. `makeTubeTexture(warm)` is THE FILAMENT — the one asset every electric light in the game shares (level-0 troffers and THE END's strips): the canvas HEIGHT is the tube's length (CylinderGeometry's v runs end-to-end), which is what makes END BLACKENING possible, and without the mercury baked onto the glass at the electrodes a tube is just a glowing stick. It must stay bright on average — lights.js drives `tubeMat.color` every frame and this map multiplies it. `texGalv` is the galvanized sheet every fixture shell wears, mapped at a fixed world scale so a 2.2m reflector spine and a 0.09m end cap carry the same steel. `texReflector` is the troffer's painted-steel backplate: like the filament it MULTIPLIES a colour lights.js drives every frame, so it must stay bright on average, and what it buys is SHAPE — a MeshBasic backplate is one flat value, so a trough pressed out of it would look identical to a flat sheet, and the two bright lanes beside the lamps, the shadow the wireway casts down the spine, the dust and the dead flies all have to be printed. `texLouvre` is the one strip every egg-crate blade wears, running near-white at the top (50mm from a burning tube) to near-black at the bottom arris — that gradient is what gives a cell visible DEPTH on a surface with no thickness. `scaleBoxUV` takes an optional `skip` face list for boxes with one FITTED face (a printed label) that must keep its 0–1 mapping while the rest tiles.
- **`scene.js`** — Three.js scene/camera/renderer, the point-light pool, and `buildLevel()` (level 0 geometry; populates the exported `lights` array). Objects present at module init are tagged `userData.persist`; `clearLevelScene()` removes everything else (the level-change teardown) and resets `lights`/`wallMeshes`/`wallDecals`. `setLevelEnvironment(level)` swaps fog/ambient profiles. `makeLightRecord()` is the single fixture-record factory: every light in the game (level-0 troffer or library hanging strip) is the same self-contained filament asset driven by lights.js — builders only choose the knobs (`bright`/`dimDen` set how yellow a panel idles; `warm`, `flickery`, `fixY`, `wakeAt`). `buildLevel()` maps the wallpaper with `paperBoxUV` (see textures.js) rather than raw box UVs, and the carpet retiled from 8m to 4m; wall, carpet and ceiling all carry bump maps now, all three tuned DOWN after seeing them in-engine (0.006 / 0.006 / 0.012 — a hard bump on any of these turns paper into stucco, carpet into mosaic and a ceiling tile into cracked eggshell). `makeTroffer()` builds the level-0 troffer from module-level `markShared`'d geometry (the mirror of library.js's `makeFixture` for the hanging strips) — only the per-fixture glow/tube/louvre materials are created per build. THE LOUVRE IS GEOMETRY, and that is the whole fixture: it used to be a flat plane wearing a printed grid of dark lines, which from directly underneath is exactly right and from anywhere else is graph paper stuck to a light. What a louvre does is CUT OFF — walk past one and the cells close as the angle steepens until the lamp disappears behind its own blades — and twenty single-quad blades (DoubleSide, 12×6 cells at a 0.22m pitch, 48mm deep) get that for ONE draw call. The housing is `bakeParts`-merged from a collar, a pan, four walls, the rim the louvre drops into and the ballast wireway (it was six draws — a box with a six-material array); the lampholders are ivory, merged, and are what says the tube is seated in something rather than floating in a box; the two tubes merge into one buffer. 5 draws a fixture, down from 10. `HOUSE_D` is 0.165 so the depths actually stack — pan, then lamps, then the blade band, with the blade tops 3mm clear of the tube bottoms. The exported `tubeTex`/`warmTubeTex` are the shared filament maps both levels' tubes wear.
- **`props.js`** — collectible/breaker/exit-elevator builders, `placeProps()`, the `interactables` array (+ `clearInteractables`/`addInteractable` for level changes), `updateProps()` idle animation. The three things you are sent to find are real objects: the almond water is a lathe-turned PROFILE (heel, straight side, shoulder, neck, lip — the whole difference between a bottle and a tin can), closed at radius 0 on the base and left open at the lip where the cap covers it, with the liquid as its own inner lathe filled to just under the shoulder (a transparent bottle you can't see a level in is a solid) and a printed label; the fuse is a glazed ceramic cartridge with brass ferrules and FLAT brass blades (flat is the tell that it's a contact and not a peg), and its origin must stay at the base with height ~0.3 because the cutscene flies that exact group into the slot; the breaker is a load centre — recessed cabinet, folded flange, knuckle hinges, printed maker's plate and circuit directory, dead breakers flanking the one live slot. `makeBreaker` keeps a hard contract with cutscene.js: `doorPivot` (a Group at (−0.45,0,0.2) swung about y), `fuse` (a Group whose every material is faded up from 0), `lamp` (a single mesh whose own material is recoloured) and `lever` (a single mesh moved in y from −0.1 to +0.1). Prop canvases are module-level and `markShared`'d — `placeProps` runs again on every respawn, and teardown disposes anything unmarked, so a rebuilt level would come back wearing dead textures. `makeElevator(p,facing,opts)` takes `{wallH, wallMat}` so THE END reuses it for the crashed arrival cab; without `opts.uvTile` its rebuilt wall pieces take level 0's WALLPAPER contract (`paperBoxUV` + each box's own `y0`), and the flanks come out at exactly two drops so the seams still land where they should. The elevator is carved into its wall cell (the wall box mesh is removed and rebuilt as flanks + header around a recessed cab; the grid cell stays solid for collision).
- **`library.js`** — THE END: `grid2` gen (one vast room; perimeter walls, shelf runs that converge/anchor into walls, table islands, the central 3-cell desk), connectivity repair, type-aware queries (`libCollide` — tables passable only while crouched, plus circle obstacles in `LIB.obstacles` for chairs/lecterns/ladders; `losCells2` — shelves block sight, tables/desk don't; best-effort `bfsPath2` that routes to the nearest standable cell when the target is unreachable; `cellAt` for the spider's leg-terrain probe), `buildLibrary()` (geometry — wall boxes get world-scaled UVs via `scaleBoxUV` so the tileable plaster never distorts; hanging fixtures pushed into `lights`; furniture, readable-nonsense posters, cracks, wall texts, vintage PCs, 16–22 floppy disks, the terminal). EVERY WOODEN THING IS JOINERY, MERGED BY MATERIAL: shelf runs get a plinth, a crown rail and a lipped front edge on every board (the shadow line under that lip is most of what tells your eye a shelf is a shelf) in 3 draws where five bare slabs cost ten; tables get a plank top with real seams, a bullnose band, a deep apron and tapering legs — and NO stretchers, because a table cell is passable to a crouched player and a bar at shin height is a bar you crawl through while hiding under the only cover in the room; the desk is panelled between stiles with a counter, nosing and transaction ledge instead of one 11m untextured slab. Plinths and crowns are held FLUSH with the collision slab (`SHELF_D/2+0.02`) — anything proud of that is something you walk your face through. THE GRAIN HAS A DIRECTION: both wood canvases are drawn grain-down-the-image, right for a stile and wrong for anything lying along its length, so horizontal members use a rotated CLONE (`shelfMatH`/`deskMatH`) — free, and without it every board in the building reads as painted MDF. `taperBox` narrows a box toward one end (legs, the CRT). `makeFixture` is a REFLECTOR now, not a lit slab with two sticks under it: a pressed spine, two wings splayed down and out (placed by their EDGES — a plate's local +z under a rotation θ about x points at (y=−sinθ, z=cosθ), so hinging one at the spine's z edge lands the outer edge exactly where the trough should open), end caps, sockets over the glass ends, a guard cage, and a drop with an eye and a ceiling plate. All of it is galvanized sheet so it merges to ONE mesh; only the backplate and the tubes stay separate, because lights.js repaints their materials every frame — 3 draws a fixture, half what the flat slab cost. `makeVintagePC` tapers the tube to its neck, recesses the glass behind a real bezel with a paraboloid bulge, and prints the keyfield rather than building 90 keycaps — 4 draws, down from 9; the screen canvas and the drive LED stay separate meshes because cutscenes write their materials. BOTH SETS OF VENTS ARE SEATED ON SURFACES DERIVED FROM THE GEOMETRY, not placed by arithmetic that never meets one. The crown SLOPES — `taperBox` pinches the CRT's −z end, so the top face runs from (+D/2, +H/2) down to (−D/2, +H/2·k) and each vent is seated on `crownY(z)`; a ladder of plates climbing in y at one fixed z put all six of them in open air above the monitor, the highest 0.1m clear of the glass, and a 0.34m board floating over a CRT is the largest unattached thing in the room. The flank slots run front-to-back along the FLANKS: spread along the case's width and extruded 0.24 in z at z=±0.251 they went straight through the front and back faces and poked 0.12m out over the keyboard. THE BEZEL STACK IS ORDERED IN Z AGAINST THE TUBE'S OWN FRONT FACE: with the glass behind it, the only part of the screen that showed was the patch where the bulge cleared it — a black OVAL floating on a beige box. `makeDisc` wears a printed label (`makeFloppyTexture`) with the shutter, hub and write-protect tab; its `top` UV band is handed to `setFaceUV` REVERSED, because a box's +y face runs v toward +z and without the swap the disk comes out end-for-end. The label keeps its phosphor emissive — that is a gameplay property (findability in the murk), not decoration, the way down (`buildHole` — the carpet is a `ShapeGeometry` cast with a circular hole two cells behind the desk, covered by a UV-matched carpet plug; beneath it a stone shaft, one merged spiral stair — and BOTH the treads and the shaft WALL are skinned in THE NEST's own rock (`texCaveRock` + bump, world-scaled UVs; `repeat.x` on the shaft cylinder must stay an INTEGER or the u wrap puts a hard vertical cut down all 22m). It has to be that rock: you step off the bottom of this flight onto the cave's continuation of it. Raw box UVs had crammed a 4m tile onto a 1.25m tread and averaged out to a flat grey slab, and the wall wore a local 128² packed-earth canvas at repeat(6,4) — 44 px/m around and 23 px/m down, the lowest resolution in the game — whose "strata" were fourteen full-width sine curves, i.e. precisely the pass `texCaveRock`'s header was written to bury, tiling into dark worms crawling round the shaft. No colour tint on it: `texCaveRock` is deliberately dark and low-contrast and the only things lighting 22m of shaft are four dim blue points, so multiplying it down as well buried the detail. Then stacked blue glow/fog discs and idle-at-zero blue point lights, all invisible until the terminal ending calls `revealHole()`; the shaft's point lights live in the scene awake-but-dark from build — revealing them inside the group would change the light count and force a full shader recompile mid-cutscene — and `buildLibrary` ends with a `renderer.compile` pre-warm pass over the hidden group for the same reason; the dig zone is excluded from prop placement via `clearOf`, and `LIB.hole` carries `{x,z,r,stair}` for the cutscenes and physics). The open stair is walkable: `libGroundY(x,z,curY)` returns the tread height under a point (lap disambiguated by the player's own height), `shaftClamp` is the below-floor wall, and `updateLibrary` densifies/blues the fog as a pure function of `-STATE.y`, and `updateLibrary()` (the 125s post-first-pickup light drop, temporary whole-floor blackouts, decor-PC boot-and-die animations, the open hole's breathing glow). Shelf visual segments are DERIVED from the final grid after repair, so collision and graphics cannot drift apart.
- **`cave.js`** — THE NEST: `grid3` gen (chamber blobs + winding tunnels; cell codes 0 open · 1 rock · 2 squeeze (crouch-only, matriarch-blocked) · 3 stream (noise-masking wade) · 4 scree (1.6× noise) · 5 void (the chasm) · 6 bridge · 7 rubble (sealed alt tunnels)), connectivity repair for BOTH the crouched player and the squeeze-blocked matriarch, and the ORGANIC TERRAIN FIELDS — the load-bearing idea of the level's geometry: `floorYAt`/`ceilYAt`/`wallField` are deterministic functions of world position (corner-grid bilinear + sine detail; `wallField` is a lateral 3D vector field, zero at the floor line, ≤0.26m through the body band so the camera can never clip, swelling to overhangs near the vault) sampled per vertex by the meshes AND queried by gameplay/placement, so geometry and collision/anchors cannot drift apart. THE STREAM is a LENS, not a sheet: the bed is locked flat at −0.25 and one ring out `isBankCell` lifts the rock clear of the water line (keeping its detail weight, unlike every other damped corner — a bank at `fW` 0 is pure bilinear and the contour across it comes out nearly axis-aligned, a shoreline with 90° jogs in it), so the shoreline is simply the contour where bank crosses water. The surface is the water LINE plus ripple and nothing else; both it and the caustic-net layer on the bed are emitted across the whole footprint and the DEPTH BUFFER cuts them — the surface passes under the rising bank, the bed layer is clamped to stay below the surface so past the waterline it sinks beneath the floor mesh. Deciding per sub-quad which to emit puts 0.67m stair-steps along the shore; lifting the surface onto the rock as a thin film flares a huge pale specular beside every fungus colony. Depth is tinted per vertex (`QuadAcc.triNC`) because r128's Phong has no vertex alpha, so the shore fades in COLOUR to the wet rock's own tone. The two layers drift at different rates and headings — that parallax IS the depth; dimming the caustics to keep it a black stream just puts the flat sheet back, so the body tint comes down instead. Floor: rolling ±0.5m corner noise damped DEAD FLAT where gameplay stands on the numbers (stream bed −0.25, bridge/chasm lips/squeezes 0, spawn+corpse, brood pads, fissure alcove — `fW` weights). Ceiling: corner min of adjacent cells' heights + jitter, with the hard clamp: any corner touching a standable cell ≥3.95m and `ceilYAt ≥ floorYAt+3.62` — the vault NEVER dips below 2× player height over walkable ground (a build-time audit console.warns if a future edit breaks this); squeeze cells close to a ~1.5m bore past a mouth ramp that lives INSIDE the squeeze cell (`de` edge-distance lerp — an upright head never meets stone; squeeze-adjacent floors are locked flat so the two ceilYAt branches agree at the boundary). Walls are displaced faceted sheets per exposed rock face (floor-welded, vault-welded, corner-continuous because vertices are functions of world position alone — no boxes anywhere). THE WELD IS A TESSELLATION CONTRACT, not just a shared field: a wall face's COLS must equal the sub-quad count of the floor AND vault over its own cell (3, or 4 in a squeeze — the floor matches that too), and ROWS is the GLOBAL `WALL_ROWS`, never per-face. Sampling the same edge curve at different intervals makes the two polylines drift apart between shared points and opens slivers you can see the void through; a per-face ROWS did the same to any column shared by two faces. A build-time weld audit is easy to redo: every wall vertex at the floor or ceiling line must coincide EXACTLY with a floor/ceiling vertex. ceiling 3×3 (squeeze 4×4) faceted sub-quads; the floor is 3×3 sub-quads too but SMOOTH-shaded from `floorNormalAt` (the height field's own gradient, sampled at build time) — fractured rock reads as planes, sediment must not. Scale: 47×47 grid, 2-cell (8m) wide spokes carved by `carveTunnel(…,wide)` with 3-wide bulges, tunnels 4.8–6.6m tall, central chamber r 6.5 cells under an 18m dome, broods r 4–4.5 under 12–13m, squeezes are 3×3 stamps across the full loop cross-section; the fissure pocket's cell is skipped so its bore stays open; entity meshes (matriarch, hatchlings) and every prop ride `floorYAt`, and `CAVE.approachC`/`CAVE.bridgeC` carry the fissure-approach/bridge cells for rockfall's protect marks (no hardcoded coordinates). Type-aware queries (`caveCollide`, `underRock`, `losCells3`, best-effort `bfsPath3(…,small)` — `small` walks the hatchlings' grid, `cellAt3`, `surfaceAt`/`surfaceNoiseGain`/`silkGainAt`), `buildCave()` (fungus colonies as **cold** light records — no buzz, `mul2` region dimming, per-colony `tint`/`poolCol` driven by lights.js; the mushrooms themselves are lathe-built varieties UV-mapped into a shared skin atlas (`makeFungusSkin` — diffuse + emissive strips for stem/gills/cap/bulb): wall conks (per-colony size class `sf` 2–10× on a skewed power law — the metre-plus ancients mount ABOVE head height and low ones >0.5m radius push obstacles), floor toadstool families, stream-bank finger coral, scree puffballs, chosen per cell code/chamber/water proximity, blushing violet within 5 cells of a brood; every colony grows 2–4 mycelium CORD ribbons (`cordGeo` — thin tapering strips that follow the displaced surface point by point, UV'd into the glowing bulb strip; glowMat is DoubleSide for them) instead of the old flat vein decal — wall colonies keep NO decal at all, floor colonies keep one small dim ground halo; each colony is one merged mesh (+ floor halo) ≤2 draws; dripstone is lathe-grown, never conical — `spireGeo`/`columnGeo`/`stumpGeo`/`moundGeo`/`curtainGeo` build drip-ringed, per-point-jittered profiles that `dripNoise` pushes out of rotational symmetry (radial noise + a slow lean), skinned by `texDripstone` (pale streaked calcite, its own bump map) on `wetMat`/DoubleSide `curtainMat`; varieties by location — chamber spire stacks on flowstone mounds with answering hangers, full floor-to-vault waisted columns (obstacle r 0.55), wall drapery curtains hung from the wall face's own edge-corner vault, flowstone cascades on stream banks, snapped stumps + toppled spires in the scree, soda-straw clusters around ceiling seeps — all merged into three meshes (floor/ceiling/curtains); webs are 3D silk STRUCTURES, never flat wall decals — `webSheetGeo` (sagging pinned sheet), `webHammockGeo`, `funnelWebGeo`, `webWrapGeo`, `webStreamerGeo`, `strandMesh` (a thin quad strung point-to-point; guy-lines) on a lit Phong silk material family (glistens under the lantern; textures.js's `makeWebSheetTexture(torn)`/`makeCobwebTexture` (top-edge anchored fan)/`makeStrandTexture`/`makeFunnelTexture`). The silk maps obey one rule: ALPHA IS THREAD-SHAPED — no broad translucent fills anywhere, and the sheets feather out at their border (`silkFeather`) so a quad's rectangle never shows as an edge. Break that and sheets go back to reading as panes of dirty glass hanging in the air. They are mipmapped (POT, anisotropy 4) so distant silk softens to haze instead of aliasing into scratches. Anything hung FREE from the vault uses `webVeilGeo` (pinned along its top edge only, so it tapers and sags), never `webSheetGeo` — a four-sides-pinned sheet hung loose reads as a flat billboard floating in mid-air. Every ceiling-hung web is sized against the LOCAL floor-to-vault room, never an absolute height: a web that reaches the ground stops reading as silk and starts reading as a wall. EVERY slung sheet in the level goes through `slung(cv,wdt,dep)` and carries four corner guy-lines up to the rock. What the eye reads as "the ceiling" is the plane of the four pinned corners MINUS the belly's sag, and the belly is the part you see from underneath — so `slung` returns a corner height 0.12–0.45m under the vault AND a sag capped so the sheet's LOWEST point is never more than ~1.05m down. Sizing the sag off the sheet's own footprint and the hang off the local vault height (the brood canopy hung at up to 0.4× a 13m dome) put big flat sheets four-plus metres out in open air on four hair-thin guys nobody reads as load-bearing; the depth over a brood must come from streamer TAILS, not from dropping the sheets. ## Key conventions

- The map coordinate system uses `cellToWorld` / `worldToCell` (level 0), `cellToWorld2` / `worldToCell2` (THE END) and `cellToWorld3` / `worldToCell3` (THE NEST) to convert between grid cells (integers) and Three.js world space (meters). `CELL` (4m) is shared by all three.
- `MeshPhongMaterial` is used deliberately over `MeshLambertMaterial` on large floor/ceiling planes — Lambert is per-vertex in Three.js r128, which produces all-or-nothing lighting on geometry with only corner vertices.
- **Nothing UNIQUE may live in a tiling map.** A one-off feature drawn into a texture that repeats becomes that feature repeating on the tile pitch, which reads louder than whatever it bought — a single lifted wallpaper seam turned into an identical lifted seam every 2m down every corridor in level 0. One-off damage goes on a decal (the mold/drip system is exactly that); a tiling map may only carry what is true everywhere.
- **A texture's resolution is px/m, not canvas size**, and the two are only related through the UV rate. Every generator in this codebase has been rewritten at least once for the same reason: features drawn below the size the eye resolves at the distance you view them from average straight back out to the flat field they started on. Check px/m before adding detail.
- **Nothing organic may have a straight edge, and no decal may end on one.** Damp, grime, mold, spills and stains drawn as `fillRect` put four visible corners on every mark — a wall covered in faint hard-edged rectangles stops being stained and becomes veneer with printing on it. Use `soft()` (canvas blur), gradients, or paths. Separately, the instant anything inside a decal still has alpha at the canvas border you see the decal's RECTANGLE, however soft the art is: every decal generator ends in `featherEdges`, naming the one edge (the seam it is butted against) that stays solid.
- **A REGULAR GRID DRAWN INTO A FLOOR OR WALL MAP IS TILE.** It has happened three times — the library's carpet, level 0's carpet (in the diffuse map *and* embossed in the bump map), and level 0's wall. A lattice at any real contrast is grout; a tuft grid at 128 px/m is a 3cm mosaic; a full-width rule every 4px is lumber. Textiles are a SCATTER with a broad metre-scale mottle under them, and paper is nearly featureless.
- **`mergeStatic` ends in `freezeStatic`**, so a `.position.set` on its result writes a matrix that is never recomposed and the mesh silently renders at its parent's origin. Bake placement into the source meshes before merging, or re-enable `matrixAutoUpdate` deliberately (spider.js's abdomen does the latter).
- Light pool pattern: `LIGHT_POOL_N` point lights are reused each frame, bound to the nearest fixtures within `LIGHT_BIND_RADIUS`, instead of one light per fixture. All levels' fixtures share the same `lights`-record shape (library records add `fixY`/`wakeAt`; cave records add `cold`/`buzz:false`/`mul2`/`region`). `cold` records KEEP the idle breathe (it is the intended slow pulse) but never enter a flicker BURST: `canBurst` is gated on `!L.cold`. Strobing is a failing ballast, and a mushroom has not got one — the bursts were inherited from the electric floors and read as wrong on a plant. Fungus reacts only through `mul2`, the region die-back when a brood burns.
- Never change the scene's light COUNT at runtime — three.js r128 keys shader programs on it and recompiles everything in one frame (a hard hitch). Reveal-later lights (the library's hole, the cave's fissure and clutch fires, the lantern) are all created up front at intensity 0 and pre-warmed with `renderer.compile`.
- Exported `let` bindings (`grid`, `grid2`, `grid3`, `exitDoor`, `lights`, `interactables`) are reassigned/mutated by their owning module; importers see live values but must not assign to them. All three grids are on `window.NOCLIP_DEBUG` (along with `W`/`H`/`CELL`/`cellToWorld`) for smoke tests.
- THE END's grid cell codes: 0 open · 1 wall · 2/3 shelf (along x/z) · 4 table · 5 desk. The spider treats every nonzero cell as solid; players pass type-4 cells only while crouched.
- THE NEST's grid cell codes: 0 open · 1 rock · 2 squeeze · 3 stream · 4 scree · 5 void · 6 bridge · 7 rubble. The matriarch treats 1/2/5/7 as solid; hatchlings pass squeezes (1/5/7 solid); players pass 2 only crouched and fall through 5.
