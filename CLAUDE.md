# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A first-person browser horror game — "NOCLIP: Escape the Backrooms" — vibe-coded with Claude Fable 5 / Claude Mythos 5. Vanilla JS ES modules with Three.js r128 from CDN; no build system, no package manager, no compilation, no image or audio assets (everything is procedurally generated).

Three levels as of v3.0.0: **LEVEL 0** (the yellow backrooms maze), **THE END** (the infinite library, entered when the exit elevator's brakes fail) and **THE NEST** (the fungus-lit cave below the library's dug stair). `STATE.level` (0/1/2) picks the active update path; the renderer, light pool, audio buses, interaction/focus, HUD and cutscene systems are shared across levels. Versioning: major = number of levels, minor = refinements to existing levels. Per-level lore documents (menu wiki entry + in-world found document, parse-ready) live in `lore/` — see `lore/README.md` for the format contract.

## Running locally

The game uses ES modules, so it must be served over HTTP (opening `index.html` via `file://` will not work):

```
npx serve .
# or
python -m http.server
```

GitHub Pages serves `index.html` at the repo root as the live site.

## Architecture

`index.html` is markup only (HUD + overlay screens); `css/main.css` holds all styling; game code lives in ES modules under `js/`, entry point `js/main.js`:

- **`utils.js`** — `$`, `clamp`, `lerp`, `angLerp`, `rand`, `hash` (the shared sin-fract noise used by flicker/cutscene/blackout jitter), and `srand` (seeded RNG used only by map gen, so layouts are reproducible).
- **`settings.js`** — `SETTINGS_KEY` + `readSettings()`: the one reader of the persisted settings blob. Exists because scene.js needs the saved graphics quality at renderer construction (antialias is fixed at GL-context creation), long before ui.js evaluates.
- **`state.js`** — the flat mutable `STATE` object (player + progression for all levels; THE NEST adds `hasLantern`/`lanternOn`/`lanternCharge`/`cranking`, `clutchesLit`, `frenzyT`, `caveT0`), `KEYS` (raw input), the `monster` state object (level 0), and the `spider` state object (THE END + THE NEST — the same individual). Everything reads/mutates these shared objects.
- **`map.js`** — level-0 grid constants (`W`, `H`, `CELL`, `WALL_H`), random-walk carve in `genMap()`, `cellToWorld`/`worldToCell` conversions, `isWall`, `losCells` (line of sight), `bfsPath` (entity pathfinding). `CELL` is shared by both levels.
- **`textures.js`** — `makeCanvas` + procedural textures via 2D canvas: level-0 wall/carpet/stain/ceiling, mold/drip decal growers, THE END's set (`texLib*`, woods, `makeCrackTexture`, `makeEndTextTexture`, `makePosterTexture`, `texBeige`, `makeKeyboardTexture`, `makeFloppyTexture`), the shared electric-light pair (`makeTubeTexture` + `texGalv` — see below), THE NEST's rock/floor/dripstone + the silk family, and the shared spider chitin maps (`texSpiderAbd`/`texSpiderCarapace`/`texSpiderLimb`), THE NEST's `texEggSac`/`makeFlameTexture`/`texCocoon`. The two lathe-dressing maps have an ORIENTATION CONTRACT: u wraps the body, v runs front→rear, so a horizontal stroke becomes a RING — the carapace's striae must be drawn as VERTICAL strokes or the head reads as a cut tree stump, which is what the first pass shipped. All the chitin maps are kept near-neutral: warm browns times the lantern's orange multiply out to BRONZE, and the spider looked cast rather than grown. `texCaveRock` is 512² because the walls are UV'd at 4m/tile — at 256 a facet you stand beside was a smooth gradient. It is built from multi-scale blotching plus SHORT angular joints drawn wrapped: never long smooth curves, which tile into visible worms crawling across every wall. `texCaveFloor` follows the same lesson at ground level — sediment lobes, runoff channels, drying cracks and proud stones with lit crowns, all MID-scale, because the old floor was 9000 sub-pixel dots that averaged to flat brown and gave the bump map nothing to bite. `texLibCarpet` learned it a third time: at 4m/tile the pile is sub-pixel, so 26 000 dots averaged straight back to the flat field they started from — what reads is BERBER FLECKS (rust/ochre/bone fibre), the loop rows, and the traffic worn into it, over a matching `texLibCarpetBump`. Its tone-on-tone lattice is deliberately near-invisible: at any real contrast it stops being a weave and becomes grout, and the floor turns to ceramic tile. `makeTubeTexture(warm)` is THE FILAMENT — the one asset every electric light in the game shares (level-0 troffers and THE END's strips): the canvas HEIGHT is the tube's length (CylinderGeometry's v runs end-to-end), which is what makes END BLACKENING possible, and without the mercury baked onto the glass at the electrodes a tube is just a glowing stick. It must stay bright on average — lights.js drives `tubeMat.color` every frame and this map multiplies it. `texGalv` is the galvanized sheet every fixture shell wears, mapped at a fixed world scale so a 2.2m reflector spine and a 0.09m end cap carry the same steel. `scaleBoxUV` takes an optional `skip` face list for boxes with one FITTED face (the troffer's trim flange, a printed label) that must keep its 0–1 mapping while the rest tiles.
- **`scene.js`** — Three.js scene/camera/renderer, the point-light pool, and `buildLevel()` (level 0 geometry; populates the exported `lights` array). Objects present at module init are tagged `userData.persist`; `clearLevelScene()` removes everything else (the level-change teardown) and resets `lights`/`wallMeshes`/`wallDecals`. `setLevelEnvironment(level)` swaps fog/ambient profiles. `makeLightRecord()` is the single fixture-record factory: every light in the game (level-0 troffer or library hanging strip) is the same self-contained filament asset driven by lights.js — builders only choose the knobs (`bright`/`dimDen` set how yellow a panel idles; `warm`, `flickery`, `fixY`, `wakeAt`). `makeTroffer()` builds the level-0 troffer shell from module-level `markShared`'d assets (the mirror of library.js's `makeFixture` for the hanging strips) — only the per-fixture glow/tube materials are created per build; its housing tiles `texGalv` on every face BUT the bottom, which carries the fitted trim flange. The exported `tubeTex`/`warmTubeTex` are the shared filament maps both levels' tubes wear.
- **`props.js`** — collectible/breaker/exit-elevator builders, `placeProps()`, the `interactables` array (+ `clearInteractables`/`addInteractable` for level changes), `updateProps()` idle animation. `makeElevator(p,facing,opts)` takes `{wallH, wallMat}` so THE END reuses it for the crashed arrival cab. The elevator is carved into its wall cell (the wall box mesh is removed and rebuilt as flanks + header around a recessed cab; the grid cell stays solid for collision).
- **`library.js`** — THE END: `grid2` gen (one vast room; perimeter walls, shelf runs that converge/anchor into walls, table islands, the central 3-cell desk), connectivity repair, type-aware queries (`libCollide` — tables passable only while crouched, plus circle obstacles in `LIB.obstacles` for chairs/lecterns/ladders; `losCells2` — shelves block sight, tables/desk don't; best-effort `bfsPath2` that routes to the nearest standable cell when the target is unreachable; `cellAt` for the spider's leg-terrain probe), `buildLibrary()` (geometry — wall boxes get world-scaled UVs via `scaleBoxUV` so the tileable plaster never distorts; hanging fixtures pushed into `lights`; furniture, readable-nonsense posters, cracks, wall texts, vintage PCs, 16–22 floppy disks, the terminal). EVERY WOODEN THING IS JOINERY, MERGED BY MATERIAL: shelf runs get a plinth, a crown rail and a lipped front edge on every board (the shadow line under that lip is most of what tells your eye a shelf is a shelf) in 3 draws where five bare slabs cost ten; tables get a plank top with real seams, a bullnose band, a deep apron and tapering legs — and NO stretchers, because a table cell is passable to a crouched player and a bar at shin height is a bar you crawl through while hiding under the only cover in the room; the desk is panelled between stiles with a counter, nosing and transaction ledge instead of one 11m untextured slab. Plinths and crowns are held FLUSH with the collision slab (`SHELF_D/2+0.02`) — anything proud of that is something you walk your face through. THE GRAIN HAS A DIRECTION: both wood canvases are drawn grain-down-the-image, right for a stile and wrong for anything lying along its length, so horizontal members use a rotated CLONE (`shelfMatH`/`deskMatH`) — free, and without it every board in the building reads as painted MDF. `taperBox` narrows a box toward one end (legs, the CRT). `makeFixture` is a REFLECTOR now, not a lit slab with two sticks under it: a pressed spine, two wings splayed down and out (placed by their EDGES — a plate's local +z under a rotation θ about x points at (y=−sinθ, z=cosθ), so hinging one at the spine's z edge lands the outer edge exactly where the trough should open), end caps, sockets over the glass ends, a guard cage, and a drop with an eye and a ceiling plate. All of it is galvanized sheet so it merges to ONE mesh; only the backplate and the tubes stay separate, because lights.js repaints their materials every frame — 3 draws a fixture, half what the flat slab cost. `makeVintagePC` tapers the tube to its neck, recesses the glass behind a real bezel with a paraboloid bulge, and prints the keyfield rather than building 90 keycaps — 4 draws, down from 9; the screen canvas and the drive LED stay separate meshes because cutscenes write their materials. THE BEZEL STACK IS ORDERED IN Z AGAINST THE TUBE'S OWN FRONT FACE: with the glass behind it, the only part of the screen that showed was the patch where the bulge cleared it — a black OVAL floating on a beige box. `makeDisc` wears a printed label (`makeFloppyTexture`) with the shutter, hub and write-protect tab; its `top` UV band is handed to `setFaceUV` REVERSED, because a box's +y face runs v toward +z and without the swap the disk comes out end-for-end. The label keeps its phosphor emissive — that is a gameplay property (findability in the murk), not decoration, the way down (`buildHole` — the carpet is a `ShapeGeometry` cast with a circular hole two cells behind the desk, covered by a UV-matched carpet plug; beneath it a stone shaft, one merged spiral stair skinned in THE NEST's own rock (`texCaveRock` + bump, world-scaled UVs — it has to be: you step off the bottom of this flight onto the cave's continuation of it, and raw box UVs crammed a 4m tile onto a 1.25m tread and averaged out to a flat grey slab), stacked blue glow/fog discs and idle-at-zero blue point lights, all invisible until the terminal ending calls `revealHole()`; the shaft's point lights live in the scene awake-but-dark from build — revealing them inside the group would change the light count and force a full shader recompile mid-cutscene — and `buildLibrary` ends with a `renderer.compile` pre-warm pass over the hidden group for the same reason; the dig zone is excluded from prop placement via `clearOf`, and `LIB.hole` carries `{x,z,r,stair}` for the cutscenes and physics). The open stair is walkable: `libGroundY(x,z,curY)` returns the tread height under a point (lap disambiguated by the player's own height), `shaftClamp` is the below-floor wall, and `updateLibrary` densifies/blues the fog as a pure function of `-STATE.y`, and `updateLibrary()` (the 125s post-first-pickup light drop, temporary whole-floor blackouts, decor-PC boot-and-die animations, the open hole's breathing glow). Shelf visual segments are DERIVED from the final grid after repair, so collision and graphics cannot drift apart.
- **`cave.js`** — THE NEST: `grid3` gen (chamber blobs + winding tunnels; cell codes 0 open · 1 rock · 2 squeeze (crouch-only, matriarch-blocked) · 3 stream (noise-masking wade) · 4 scree (1.6× noise) · 5 void (the chasm) · 6 bridge · 7 rubble (sealed alt tunnels)), connectivity repair for BOTH the crouched player and the squeeze-blocked matriarch, and the ORGANIC TERRAIN FIELDS — the load-bearing idea of the level's geometry: `floorYAt`/`ceilYAt`/`wallField` are deterministic functions of world position (corner-grid bilinear + sine detail; `wallField` is a lateral 3D vector field, zero at the floor line, ≤0.26m through the body band so the camera can never clip, swelling to overhangs near the vault) sampled per vertex by the meshes AND queried by gameplay/placement, so geometry and collision/anchors cannot drift apart. Floor: rolling ±0.5m corner noise damped DEAD FLAT where gameplay stands on the numbers (stream bed −0.25, bridge/chasm lips/squeezes 0, spawn+corpse, brood pads, fissure alcove — `fW` weights). Ceiling: corner min of adjacent cells' heights + jitter, with the hard clamp: any corner touching a standable cell ≥3.95m and `ceilYAt ≥ floorYAt+3.62` — the vault NEVER dips below 2× player height over walkable ground (a build-time audit console.warns if a future edit breaks this); squeeze cells close to a ~1.5m bore past a mouth ramp that lives INSIDE the squeeze cell (`de` edge-distance lerp — an upright head never meets stone; squeeze-adjacent floors are locked flat so the two ceilYAt branches agree at the boundary). Walls are displaced faceted sheets per exposed rock face (floor-welded, vault-welded, corner-continuous because vertices are functions of world position alone — no boxes anywhere). THE WELD IS A TESSELLATION CONTRACT, not just a shared field: a wall face's COLS must equal the sub-quad count of the floor AND vault over its own cell (3, or 4 in a squeeze — the floor matches that too), and ROWS is the GLOBAL `WALL_ROWS`, never per-face. Sampling the same edge curve at different intervals makes the two polylines drift apart between shared points and opens slivers you can see the void through; a per-face ROWS did the same to any column shared by two faces. A build-time weld audit is easy to redo: every wall vertex at the floor or ceiling line must coincide EXACTLY with a floor/ceiling vertex. ceiling 3×3 (squeeze 4×4) faceted sub-quads; the floor is 3×3 sub-quads too but SMOOTH-shaded from `floorNormalAt` (the height field's own gradient, sampled at build time) — fractured rock reads as planes, sediment must not. Scale: 47×47 grid, 2-cell (8m) wide spokes carved by `carveTunnel(…,wide)` with 3-wide bulges, tunnels 4.8–6.6m tall, central chamber r 6.5 cells under an 18m dome, broods r 4–4.5 under 12–13m, squeezes are 3×3 stamps across the full loop cross-section; the fissure pocket's cell is skipped so its bore stays open; entity meshes (matriarch, hatchlings) and every prop ride `floorYAt`, and `CAVE.approachC`/`CAVE.bridgeC` carry the fissure-approach/bridge cells for rockfall's protect marks (no hardcoded coordinates). Type-aware queries (`caveCollide`, `underRock`, `losCells3`, best-effort `bfsPath3(…,small)` — `small` walks the hatchlings' grid, `cellAt3`, `surfaceAt`/`surfaceNoiseGain`/`silkGainAt`), `buildCave()` (fungus colonies as **cold** light records — no buzz, `mul2` region dimming, per-colony `tint`/`poolCol` driven by lights.js; the mushrooms themselves are lathe-built varieties UV-mapped into a shared skin atlas (`makeFungusSkin` — diffuse + emissive strips for stem/gills/cap/bulb): wall conks (per-colony size class `sf` 2–10× on a skewed power law — the metre-plus ancients mount ABOVE head height and low ones >0.5m radius push obstacles), floor toadstool families, stream-bank finger coral, scree puffballs, chosen per cell code/chamber/water proximity, blushing violet within 5 cells of a brood; every colony grows 2–4 mycelium CORD ribbons (`cordGeo` — thin tapering strips that follow the displaced surface point by point, UV'd into the glowing bulb strip; glowMat is DoubleSide for them) instead of the old flat vein decal — wall colonies keep NO decal at all, floor colonies keep one small dim ground halo; each colony is one merged mesh (+ floor halo) ≤2 draws; dripstone is lathe-grown, never conical — `spireGeo`/`columnGeo`/`stumpGeo`/`moundGeo`/`curtainGeo` build drip-ringed, per-point-jittered profiles that `dripNoise` pushes out of rotational symmetry (radial noise + a slow lean), skinned by `texDripstone` (pale streaked calcite, its own bump map) on `wetMat`/DoubleSide `curtainMat`; varieties by location — chamber spire stacks on flowstone mounds with answering hangers, full floor-to-vault waisted columns (obstacle r 0.55), wall drapery curtains hung from the wall face's own edge-corner vault, flowstone cascades on stream banks, snapped stumps + toppled spires in the scree, soda-straw clusters around ceiling seeps — all merged into three meshes (floor/ceiling/curtains); webs are 3D silk STRUCTURES, never flat wall decals — `webSheetGeo` (sagging pinned sheet), `webHammockGeo`, `funnelWebGeo`, `webWrapGeo`, `webStreamerGeo`, `strandMesh` (a thin quad strung point-to-point; guy-lines) on a lit Phong silk material family (glistens under the lantern; textures.js's `makeWebSheetTexture(torn)`/`makeCobwebTexture` (top-edge anchored fan)/`makeStrandTexture`/`makeFunnelTexture`). The silk maps obey one rule: ALPHA IS THREAD-SHAPED — no broad translucent fills anywhere, and the sheets feather out at their border (`silkFeather`) so a quad's rectangle never shows as an edge. Break that and sheets go back to reading as panes of dirty glass hanging in the air. They are mipmapped (POT, anisotropy 4) so distant silk softens to haze instead of aliasing into scratches. Anything hung FREE from the vault uses `webVeilGeo` (pinned along its top edge only, so it tapers and sags), never `webSheetGeo` — a four-sides-pinned sheet hung loose reads as a flat billboard floating in mid-air. Every ceiling-hung web is sized against the LOCAL floor-to-vault room, never an absolute height: a web that reaches the ground stops reading as silk and starts reading as a wall. EVERY slung sheet in the level goes through `slung(cv,wdt,dep)` and carries four corner guy-lines up to the rock. What the eye reads as "the ceiling" is the plane of the four pinned corners MINUS the belly's sag, and the belly is the part you see from underneath — so `slung` returns a corner height 0.12–0.45m under the vault AND a sag capped so the sheet's LOWEST point is never more than ~1.05m down. Sizing the sag off the sheet's own footprint and the hang off the local vault height (the brood canopy hung at up to 0.4× a 13m dome) put big flat sheets four-plus metres out in open air on four hair-thin guys nobody reads as load-bearing; the depth over a brood must come from streamer TAILS, not from dropping the sheets. (The stalactites were never involved — they hang from the same vault the webs are pinned to.); placement by junction type — corner sheets strung across the chord where two wall faces meet, wall-ceiling fans pinned along the face's edge-corner vault (order `YXZ`, yaw then tilt), floor skirts + funnel retreats at the wall base, hammocks on 4 real guy-lines, streamers thickest in low tunnels, torn veils + loose strands choking squeeze mouths (their own scan — the solid-neighbor loop skips code 2), rare silk wraps + stakes on brood-side stalagmites (found via `CAVE.obstacles` r 0.45/0.55), a layered hammock CANOPY directly over each brood, a per-chamber DOME RIGGING pass (`c.r²·2.1·density` slung sheets / hanging veils / long streamers / vault-to-vault lines — the den reads from the ceiling), and the arrival mouth silked shut; density = brood proximity (radius 16 cells, floor 0.12); merged into 7 draws (2 sheet + 2 fan + torn + strands + funnels); the ARRIVAL SHAFT — `CAVE.stairMouth` `{x,z,rCut,lip}` is fixed right after `genCave()` so the vault pass cuts a round mouth around it (sub-quads whose center is within `rCut`) and every ceiling-hung placement (`inMouth`) keeps clear; through the cut runs the library's own descent bore, wrong side out — a BackSide stone throat with stacked darkening haze discs + a black cap (the library's dark, not the cave's), a flowstone collar (DoubleSide `curtainMat` ring, inner lip inside the bore's foot, outer skirt above the surrounding ceiling so no seam shows) and the same spiral stair (rise 4.48/turn, 16 treads, r 2.08, phase locked to height) whose lowest flight is collapsed — sagging break treads, fallen treads half-sunk at the foot, silk guys trussing the hang — decorative only (the debris obstacle is pushed with the mouth, before prop placement); chamber domes additionally grow partner-less stalactite fields (hanger clusters `c.r*5.2`); the corpse's position (`CAVE.corpseP`, beside the dead stair) and obstacle — AND the four clutch keep-out circles — are fixed right after the mouth so no dripstone or web can grow through them; anything whose obstacle is pushed with the prop itself (the last build step) has already had a full floor-to-vault column grown up through the middle of it, which is what happened to the egg piles. The dropped lantern holds a visible dying EMBER — glass-glow mesh + a warm breathing PointLight (`CAVE.corpse.glowL`, animated in `updateCave`, set to 0 on pickup, never removed: light count) — beside a real journal prop; 4 egg clutches; cocoon bundles that either LIE DOWN on the floor (they are 1.5–2m long — stood on end at floor+0.45 half of each was underneath the rock) or hang with two real silk lines running the whole way to the vault, never parked in mid-air with nothing attached; rubble piles; the hidden fissure chimney with in-scene dark lights + `renderer.compile` pre-warm, same recompile-avoidance as the library's hole), `igniteClutch()` (fire + frenzy + `CAVE.lastBurn` for the matriarch + region fungus dim + `rockfall()` — closes a corridor only if a crouch-flood still reaches every remaining objective, opens that burn's sealed tunnel), `openFissure()`, `hushCave()` (see lifecycle.js), and `updateCave()` (frenzy clock, fires burning down — gain fed the fire's DISTANCE and pan, not just its fuel — fungus dim ramps, chasm fall death at y<−9, stream gain by distance, drip scheduler, rockfall shake). A burned clutch stays visibly burned FOREVER: past `burnT` 3 the eggs shrivel to 0.58× and settle into the mound, permanently. It is already `taken`, so there is no prompt to explain itself — and the old cooled-out state (a full pile of plump eggs in a slightly darker brown) was indistinguishable from a live clutch under an orange lantern, which reads as a bugged objective after a respawn. Respawn keeps every burn; nothing about it resets a brood. The fissure's chimney is walkable: `caveGroundY` is the library stair's lap-disambiguation math inverted (treads rise), `caveShaftClamp` is the bore wall above the alcove ceiling.
- **`hatchling.js`** — THE NEST's brood: 5–6 cat-sized, photophobic mini-spiders (`HATCH`), one per brood chamber plus tunnel wanderers. Territorial leash + sound pursuit (no BFS — slide-along-cells steering); clutch fires physically repel them; one that reaches you **latches** (mesh rides the camera shoulder, stamina bleeds at 0.30/s — faster than rest regen — and a screech loop feeds `spider.lastKnown` every frame) until shaken off (accumulated |Δyaw| > 5.5) or burned off (lantern on ≥1.1s), then 16s of cooldown; a latch is the ONLY channel by which the brood tells the matriarch where you are. Frenzy (`STATE.frenzyT>0`) doubles their hearing, +40% speed, drops the leash. **A LIT LANTERN IS INVISIBILITY**: while `STATE.lanternOn`, `hearR` is zero (they cannot acquire at all), an `approach` breaks off, and the `shy` rule walks anything within 11.5m back out of the glow — recoiling at 4.6 m/s inside `inBeam`, drifting at 2.6 outside it — with the state machine SKIPPED for that frame. Running the pursuit move and the shove in the same frame is what made them creep away at 0.9 m/s and hold station on the radius with aggro live; and a lamp-driven `flee` must not beeline home, because half the nests sit inside the glow (it goes to `lurk`, whose wander anchors on the hatchling's own position while the lamp burns). The leg is ONE geometry — a cylinder bent along a femur-up/tibia-down polyline (`hatchLegGeo`, module-level and `markShared`) — so the stance pose can't be inverted by a sign and `fem.rotation.z` only ever LIFTS the foot; the old single straight cylinder at +0.55 rad had the whole brood swimming on its back. THEY HAVE THEIR MOTHER'S EIGHT EYES. They were built with nothing where eyes should be, and at hatchling scale that left two pale spheres with legs — a blob. The eight of them (in her two rows, plus chelicerae, fangs and pedipalps) are what makes a shape in the dark resolve as an ANIMAL, and it costs the lore nothing: the eyes are WHY the light hurts, and a thing that hunts by sound 60m down has no more use for them than it ever did. A faint eyeshine emissive means a distant one is eight pinpricks before it is anything else. Head parts follow the matriarch's rule — an eye is seated by projecting its direction onto the cephalothorax ellipsoid (p = c + R·d̂), every spike is built along +Y from its base and then aimed, so nothing can come out inside-out or buried under the skin — and the whole face merges into TWO geometries (one per material), 2 draws rather than 14. THE NEST HAS NO SUSTAINED NOISE BEDS except the sub-bass rumble (lowpassed at 48Hz). Filtered white noise held at a steady level is a HISS, and down here every one of them ended up parked on a clutch room: the librarian's skitter bed (bandpass 2500Hz under an 11Hz tremolo) is silenced in `updateSpiderCave` — the matriarch's tending round is a patrol BETWEEN THE CLUTCHES, so it sits near a brood for minutes and the bed just sits there with it (THE END keeps its bed; there it works and the complaint has never been about the library) — and the stream is lowpassed with a slow swell and audible only inside 11m with a squared falloff, where at the old bandpass-1500Hz/26m it washed brood rooms 12 and 14m off the water through every ignite. The matriarch's proximity is carried by the dread vignette, the heartbeat and its own discrete footfalls. THE BROOD HAS EXACTLY TWO VOICES — their footfalls and the screech of one that's latched onto you — and nothing should add a third. Their recoil from the light is something you SEE, not hear: the old `sfxHatchHiss` cue is five 5.2kHz ticks inside 200ms, and repeating it every 0.8–1.6s for as long as a hatchling stood in the lantern turned the level into a bag of beads being shaken. Skitters (`sfxHatchTap`) schedule off ground ACTUALLY covered (`hatchMove` returns it — one wedged against rock has not stepped), over a randomized stride, behind a per-hatchling cooldown that scales with range and one `tapGate` shared by the whole brood: flat-and-frequent is what turned six of them into a bag of beads.
- **`lantern.js`** — the crank lantern: `toggleLantern()` ([F]), `updateLantern()` (charge drain ≈95s, crank recharge ≈22s while holding [R] — loud, speed-capped, `STATE.cranking` is a hearing event for both AIs), `inBeam()` (an AOE radius+LOS test, r 9 — despite the legacy name there is no cone), HUD charge bar classes. It is a LANTERN, not a flashlight: the dominant light is a warm orange PointLight pool centred on the hands (plus a very wide soft SpotLight forward wash — no cone edge), and its intensity breathes on slow incommensurate sine + hash noise like a real mantle, guttering hard only below 18% charge. Both lights are created at module init and live in the scene from the first frame at intensity 0 — the light count never changes, so toggling can never trigger a shader recompile.
- **`spider.js`** — THE END's librarian: horse-sized spider mesh with a procedural 8-leg gait, and the hearing-driven AI in `updateSpider()`. The mesh is anatomical, not primitives: abdomen and carapace are LATHES turned onto the body axis (`bodyLathe`, u around the body with u=0.5 dorsal, v front→rear) so `texSpiderAbd`'s folium and `texSpiderCarapace`'s striae land correctly; 8 eyes in two rows, chelicerae, pedipalps, and legs with a tarsus/claw and bristles. Everything below `femG` is rigid (tibG's rotation is fixed at build), so each leg MERGES to one draw — 12 draws total vs 34 before. Every body lathe CLOSES at both poles (profile radius 0.001 at t=0 and t=1) — a profile starting at a non-zero radius leaves an open ring, and with backfaces culled you see straight through it, which is what put a hole in the middle of the face. Eyes are seated on the shell by projecting their offset onto the carapace ellipse at their own z (`carRadiusAt`) rather than by hand-picked xyz, which buried the laterals inside the skin; they are flattened lenses aimed along the surface normal. Head parts are placed by a POINT and a DIRECTION (`aim`/`end`/`spike`/`seg`), never by Euler angles — hand-written rotations are how the chelicerae ended up inverted (tip welded to the face, fat base swinging free) and the pedipalps buried in the carapace; `spike`/`seg` build from the attachment outward along +Y and then aim +Y, so a part cannot come out inside-out. The animation contract the gait depends on is `userData` `{legs[{hip,femG,basePhi,phase,front,row,fold}], eyeMat, abd, head, BODY_Y, scratchAnim, sniffAnim, abdTilt}`; `abd.scale` is overwritten every frame to (1, 0.9, 1.35) and `TAIL_LOCAL` assumes the abdomen's rear sits at local z −0.8, so it cannot be resized without moving both. THE NEST reuses the same mesh/gait with a separate state machine in `updateSpiderCave()` (tend/tending patrol between unburned clutches · seek/investigate/chase · frenzy→rampage on `CAVE.lastBurn` · permanent `hunt` once all four burn): hearing = 0.8× dulled in open cave, ×2 through silk-laced nest floors (`silkGainAt` at the PLAYER's cell), scree/stream surface gains, cranking heard flat at 18m, sustained lantern light (>5s, LOS, <40m) steers it in, a latched hatchling feeds it your position continuously; squeezes are its table-cells (impassable, sight-blocking, kill-proof). Its UNHURRIED gaits down here are 20% slower than the run (tend 4.5 · mild seek 4.58 · rampage 5.4 · hunt 5.8): at the old 7.2 the hunt was within a whisker of the 7.28 chase and read as a pursuit that never resolved. Chase/frenzy/seekRun keep RUN_BASE — those ARE the chase, and the escape is measured against them. `hunt` quarters the cave around the cell the PLAYER stands in, so left alone it camps: against a crouched, motionless player it cannot see (3.6m) or hear (silent) it circled one chamber indefinitely, shrieking, never closing — and it never released `lastKnown` after working it, so even the quartering was tethered to one corner. Two rules fix it, both in the `hunt` case: a self-directed target is COMMITTED (walked down to within 3.5m or an 18s timeout) instead of re-rolled every 1.7s, and consecutive player-anchored rolls are capped at `ROOM_CAP` 3 — the next target is then forced to a chamber that is neither the spider's nor the player's (`otherRoomCell3`). Count the ROLLS, not the room the target lands in: booking targets against a room key silently did nothing, because the ±6-cell quartering scatters most targets into tunnel buckets outside the chamber and the counter reset every pick. Measured against a crouched player at a chamber centre: survives 26.6s → 111.6s, and in a corner 30.1s → the full 300s test, while a player who MOVES is still caught in ~29s either way. `resetSpiderCave` re-seeds its rounds (and clears the roam ledger). Disc pickups alert it after a flat 1s reaction (a pickup beyond 45% of the room span sends it on a wall/ceiling transit instead of a floor seek); stacked pickups before it starts moving cut the countdown by 1s each and add +0.25× speed; pickups while it's en route retarget it and add +0.25× (run base 7.28 m/s = 1.4× its browse pace, cap 2×). Uncrouched movement alerts it strongly within ~16.5–17m / mildly out to ~25m (base radii 13.6/20.4 × movement & surface gains); crouched movement is silent. It cannot enter table cells — a hidden player gets a circling `stalk` that times out. The table keep-out (`pushFromTables`) must stay inside the table's cell (margin ≤0.45); because that keep-out holds the body at exactly 2.0m from a table centre, seek arrival has a wider 3.2m radius for heard spots ON a table (the 2.0m close-approach can never fire there), and the anti-deadlock watchdog drops any path it can't physically close — escalating a pinned seek within 6m of its spot straight to `investigate` so a search episode always terminates.

THREE is a global (classic CDN `<script>` loads before the module graph) — modules do not import it.

There are intentional function-level circular imports (`monster ↔ lifecycle`, `ui ↔ lifecycle`, `cutscene ↔ lifecycle`, `spider ↔ lifecycle`, `library → ui → lifecycle → library`, `cave ↔ lifecycle`, `cave → ui → lifecycle → cave`, `spider → cave`/`spider → hatchling` one-way); they are safe because nothing in the cycle is called during module evaluation. Don't add top-level calls across these boundaries.

## Key conventions

- The map coordinate system uses `cellToWorld` / `worldToCell` (level 0), `cellToWorld2` / `worldToCell2` (THE END) and `cellToWorld3` / `worldToCell3` (THE NEST) to convert between grid cells (integers) and Three.js world space (meters). `CELL` (4m) is shared by all three.
- `MeshPhongMaterial` is used deliberately over `MeshLambertMaterial` on large floor/ceiling planes — Lambert is per-vertex in Three.js r128, which produces all-or-nothing lighting on geometry with only corner vertices.
- Light pool pattern: `LIGHT_POOL_N` point lights are reused each frame, bound to the nearest fixtures within `LIGHT_BIND_RADIUS`, instead of one light per fixture. All levels' fixtures share the same `lights`-record shape (library records add `fixY`/`wakeAt`; cave records add `cold`/`buzz:false`/`mul2`/`region`). `cold` records KEEP the idle breathe (it is the intended slow pulse) but never enter a flicker BURST: `canBurst` is gated on `!L.cold`. Strobing is a failing ballast, and a mushroom has not got one — the bursts were inherited from the electric floors and read as wrong on a plant. Fungus reacts only through `mul2`, the region die-back when a brood burns.
- Never change the scene's light COUNT at runtime — three.js r128 keys shader programs on it and recompiles everything in one frame (a hard hitch). Reveal-later lights (the library's hole, the cave's fissure and clutch fires, the lantern) are all created up front at intensity 0 and pre-warmed with `renderer.compile`.
- Exported `let` bindings (`grid`, `grid2`, `grid3`, `exitDoor`, `lights`, `interactables`) are reassigned/mutated by their owning module; importers see live values but must not assign to them.
- THE END's grid cell codes: 0 open · 1 wall · 2/3 shelf (along x/z) · 4 table · 5 desk. The spider treats every nonzero cell as solid; players pass type-4 cells only while crouched.
- THE NEST's grid cell codes: 0 open · 1 rock · 2 squeeze · 3 stream · 4 scree · 5 void · 6 bridge · 7 rubble. The matriarch treats 1/2/5/7 as solid; hatchlings pass squeezes (1/5/7 solid); players pass 2 only crouched and fall through 5.
