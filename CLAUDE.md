# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A first-person browser horror game — "NOCLIP: Escape the Backrooms" — vibe-coded with Claude Fable 5 / Claude Mythos 5. Vanilla JS ES modules with Three.js r128 from CDN; no build system, no package manager, no compilation, no image or audio assets (everything is procedurally generated).

Three levels as of v3.0.0: **LEVEL 0** (the yellow backrooms maze), **THE END** (the infinite library, entered when the exit elevator's brakes fail) and **THE NEST** (the fungus-lit cave below the library's dug stair). `STATE.level` (0/1/2) picks the active update path; the renderer, light pool, audio buses, interaction/focus, HUD and cutscene systems are shared across levels. Versioning: major = number of levels, minor = refinements to existing levels. Per-level lore documents (menu wiki entry + in-world found document, parse-ready) live in `lore/` — see `lore/README.md` for the format contract.

## Running locally

The game uses ES modules, so it must be served over HTTP (opening `index.html` via `file://` will not work):

```
npx serve .
# or
python -m http.server
```

GitHub Pages serves `index.html` at the repo root as the live site.

## Architecture

`index.html` is markup only (HUD + overlay screens); `css/main.css` holds all styling; game code lives in ES modules under `js/`, entry point `js/main.js`:

- **`utils.js`** — `$`, `clamp`, `lerp`, `angLerp`, `rand`, `hash` (the shared sin-fract noise used by flicker/cutscene/blackout jitter), and `srand` (seeded RNG used only by map gen, so layouts are reproducible).
- **`settings.js`** — `SETTINGS_KEY` + `readSettings()`: the one reader of the persisted settings blob. Exists because scene.js needs the saved graphics quality at renderer construction (antialias is fixed at GL-context creation), long before ui.js evaluates.
- **`state.js`** — the flat mutable `STATE` object (player + progression for all levels; THE NEST adds `hasLantern`/`lanternOn`/`lanternCharge`/`cranking`, `clutchesLit`, `frenzyT`, `caveT0`; `guide` is the HUD's one legitimate pointer and `deathCause` picks the death camera), `KEYS` (raw input), the `monster` state object (level 0), and the `spider` state object (THE END + THE NEST — the same individual). Everything reads/mutates these shared objects.
- **`map.js`** — level-0 grid constants (`W`, `H`, `CELL`, `WALL_H`), random-walk carve in `genMap()`, `cellToWorld`/`worldToCell` conversions, `isWall`, `losCells` (line of sight), `bfsPath` (entity pathfinding). `CELL` is shared by both levels.
- **`textures.js`** — `makeCanvas` + procedural textures via 2D canvas: level-0 wall/carpet/stain/ceiling (plus the fine detail layers the level-0 shaders lay over them: `texCarpetPile`, `texCeilFoam`, `texMoldGrain`), mold/drip decal growers, THE END's set (`texLib*`, woods, `makeCrackTexture`, `makeEndTextTexture`, `makePosterTexture`, `texBeige`, `makeKeyboardTexture`, `makeFloppyTexture`, and THE END's graphics-pass set: `makeWrapTexture` · `texTape` · `texCartPaint` · `texMannequin`), the shared electric-light pair (`makeTubeTexture` + `texGalv` — see below), THE NEST's rock/floor/dripstone + the silk family, and the shared spider chitin maps (`texSpiderAbd`/`texSpiderCarapace`/`texSpiderLimb`, the last dressing a SWEEP — v down the whole limb at 1.5m a repeat, u=0 dorsal — and carrying no bands; plus `texSpiderFur`, not a colour map but a field of strand cross-sections whose value is the strand's LENGTH, for the abdomen's shell fur), THE NEST's `texEggSac`/`makeFlameTexture`/`texCocoon`. The two lathe-dressing maps have an ORIENTATION CONTRACT: u wraps the body, v runs front→rear, so a horizontal stroke becomes a RING — the carapace's striae must be drawn as VERTICAL strokes or the head reads as a cut tree stump, which is what the first pass shipped. All the chitin maps are kept near-neutral: warm browns times the lantern's orange multiply out to BRONZE, and the spider looked cast rather than grown. `texCaveRock` is 512² because the walls are UV'd at 4m/tile — at 256 a facet you stand beside was a smooth gradient. It is built from multi-scale blotching plus SHORT angular joints drawn wrapped: never long smooth curves, which tile into visible worms crawling across every wall. `texCaveFloor` follows the same lesson at ground level — sediment lobes, runoff channels, drying cracks and proud stones with lit crowns, all MID-scale, because the old floor was 9000 sub-pixel dots that averaged to flat brown and gave the bump map nothing to bite. `texLibCarpet` learned it a third time: at 4m/tile the pile is sub-pixel, so 26 000 dots averaged straight back to the flat field they started from — what reads is BERBER FLECKS (rust/ochre/bone fibre), the loop rows, and the traffic worn into it, over a matching `texLibCarpetBump`. Its tone-on-tone lattice is deliberately near-invisible: at any real contrast it stops being a weave and becomes grout, and the floor turns to ceramic tile. LEVEL 0's tiling surfaces keep their ORIGINAL DESIGNS, and the reason is a Key convention below — what changed is resolution and material only. `texWall` is 2048² of the same eight flat stripes (512 px/m, was 64; 1024² on the low graphics setting via `LOW_TEX`) carrying only what real wallpaper has: a faint FIVE-petal floral print on a half-drop in the pale stripes (drawn in 1024-canvas units and scaled ×2.25, at a 101-unit pitch; `top`/`bot` are measured off the sprig's own −8.2…+15 extent, so at that size they keep the petals off the wall angle and the stem out of the skirting) (never four petals — a rosette turned 45° is an X, and columns of X's down a wall in this place read as a message), a double pinstripe in the dark ones, paper grain, soft dirt, a skirting with a lit lip and streak scuffs (filled ovals there read as a row of spots), and the drop ceiling's wall angle along the top. NO mark in it is a filled shape: at this resolution a solid dab is a visible rectangle or oval from a metre away, so dirt is radial falloff and the paper's tooth is a per-pixel grain laid by `addGrain` — a 512² block of signed white noise composited edge to edge, the positive half with `lighter` and the negative half with `difference` (exact because every pixel is brighter than the grain is deep). NEVER `getImageData` a big GPU canvas to walk it pixel by pixel: the read-back forces every queued draw to rasterise and was 90% of this map's startup cost (86ms → 18ms). Every horizontal pitch in it divides the canvas width, so the print runs on unbroken from one wall box into the next. `texCarpet` (512² over an 8m tile) and `texStains` are still the originals, and the floor wears them under `texCarpetPile`: a 0.5m tile of tufts that `carpetMaterial()` (scene.js) both multiplies into the colour and uses as the BUMP at its own repeat — three's maps all share the colour map's UVs, so the bump chunk is rewritten to sample `vPileUv` — divided by its mean so it vanishes into the original wherever the mip chain has averaged it out. It is MATTE on purpose: a 1024² carpet with a damp sheen was tried and read as sealed concrete with the colours laminated on; carpet has no sheen, it has DEPTH; `texCeilStains` stays 512². Both stain maps are blended INTO their surface's shader (`carpetMaterial`, `ceilingMaterial`, at `STAIN_REP`/`CSTAIN_REP` across the level): they were transparent sheets laid over the floor and ceiling, which shaded every floor and ceiling pixel twice — half the frame once lighting was trimmed. Under a ceiling stain the tile's faint specular is scaled by (1−alpha), as the sheet covered it. The wall and ceiling maps take anisotropy (≤8) in scene.js — they are mostly seen at a grazing angle, where an isotropic mip chain smears them to mud. The 4×-resolution rebuild of the wall shipped as veneered plywood (half-metre drop seams read as panel lines, ±8 per channel of batch drift made four drops read as four PANELS, a full-width "paper weave" rule every 4px was 256 courses of machined lumber, and sixty `fillRect` grime blocks along the skirting put four visible corners on every mark); the carpet went the whole way to CERAMIC TILE (a half-metre tone-on-tone lattice is grout, drawn in the diffuse map *and* embossed in the bump map in both axes; a 4px tuft grid is a 3cm mosaic; a 198-grey fleck is terrazzo aggregate); and the 1024² stain overlays grew CROP CIRCLES, because at ~40 px/m the big field stamps run three or four metres across and a closed tide line round one of those is a ring on the floor you can see from the far end of the corridor. The carpet keeps exactly two things the original lacked: a 54-stamp BROAD MOTTLE laid down first, and yarn flecked across five tones instead of flipped between two — an even speckle at one alpha over one flat colour is a product swatch, and what makes a floor look LAID is that it is blotchy at the metre scale. Both fleck extremes are held well off black and white: at 64 px/m a 2px dab is 3cm of floor, and a hard dark speck that size is not a fibre, it is GRIT, and the whole floor goes over to wet sand.
  `texCeil`/`texCeilBump` are the one part of that pass that stayed, and they are 1024² over the 4m repeat (256 px/m, 1m tiles, sixteen to a canvas), because a drop ceiling needs three things a drawn grid can't give — the grid is HARDWARE (a metal cap with the tile edge falling away into shadow either side; that reveal is the entire illusion of depth), every tile is a different tone, and the FACE IS MINERAL FIBRE. That face is `ceilFace`, and both maps are drawn from ONE per-tile SEEDED sequence: they used to roll their own randoms, so the relief and the print described two different tiles — a slit shaded dark in one place and a groove pressed in another — which is most of why the face read as smooth plaster with scratches on it, and plaster does not take the brown tide rings and mold this level hangs on it. Every random in there is drawn UNCONDITIONALLY and up front or the two passes diverge. What reads is a needle-PERFORATION field (2px, a third of them carrying the burr the needle pushed up — at 256 px/m a real 1.5mm hole is under half a pixel, so these are the pattern, not the holes), lumpy WOOL under it and short FIBRE at every angle. The FISSURES are not in this map at all: at 4mm a pixel a fissure can only be a 10–40cm slit, and those read first as BARK (56 a tile, kinked and lipped) and then, thinned out, as SCRATCHES across a smooth panel. A real one is 1–3cm and wormy. They live in `texCeilFoam` — the face at 1 px/mm (1024² over ONE 1m tile, 512² on low; built entirely in a Float32 field — `dab` for the soft round marks, `strokeField` for the fissures and wool, a union of anti-aliased round-capped segments exactly as one canvas `stroke()` covers — so the canvas only receives the result and its `mean` needs no read-back): an orange-peel mat, short worm fissures every way (a soft trough with a dark floor, never a lip), pits with a dished rim, fewer deeper pinholes and loose wool, grey, used as tone AND bump. `ceilingMaterial()` (scene.js) lays it over each tile at a quarter-turn and offset hashed off the tile's index, so no two neighbours match and the tee hides the cut, and masks it off the tee (`FOAM_REV`), which is steel. Its strength is held at 0.3 of tone and a 0.008 bump: at 0.5/0.02 the whole ceiling went over to STUCCO.
  **The decals** (`makeMoldTextures`, `makeDripTextures`) keep the original growth exactly, drawn at 1.5× the original ~72 px/m (`DECAL_K`) with EVERY pixel constant in them scaled by the same K — cap sizes, radii, jitters, step pitches — so a colony comes out the same shape, only sharper. A mold dab is a dense core under a soft margin now, each colony has its own green-to-black cast, and a drip run is one tapering ribbon (it was stacked 3px rects: a column of bricks with a sawtooth down both edges). Clamped and mipmap-free (their canvases aren't power-of-two, so WebGL1 would resize and blur them). They are grown per decal and then PACKED: `mergeDecals()` (scene.js, called at the end of `placeProps` after the elevator carve) shelf-packs every canvas into 2048-wide atlas pages trimmed to their used height, each canvas ringed by 2px copies of its own edge pixels (what ClampToEdge gave it alone), remaps the quad UVs and merges one mesh per page per kind. Drawn one material each, ~300 decals were half the frame — every draw re-uploaded the 30-light uniform block — and ~300 texture uploads at build. Anything that needs the individual decal meshes (`wallDecals`, `removeDecalsOnWall`) must run before the merge. `texMoldGrain` is built in a float field too (`dab` with `max`, the lighten blend): 135ms → 18ms. They were regrown at 150/140 px/m with damp haloes, spore stipple, hyphal margins and mineral-edged rivulets — ~30MB of canvas against 7 — and all of it came back out: what belongs at that skirting is the small dark growth that was always there. THE GROWTH LOGIC WAS NEVER THE PROBLEM and has never been touched in either direction; the shapes, sizes, counts and placement are the original's. What was wrong was the RENDERING: a canvas of soft dabs is an airbrushed smudge, and up close the mold was a blur. `texMoldGrain` (512² over 0.7m, world-mapped off whichever axis the decal faces so a colony runs on across a wrap) is a THRESHOLD field — cones for a big colony with satellites, then medium and fine spatter — and the mold shader shows a point once coverage×1.25 + grain×0.92 clears 1: a thin dusting becomes a few isolated specks, the core swells and merges solid, the grain's G channel roughs every edge, and the soft field stays under it at 0.62 as the stain so a colony keeps its footprint. The tone lifts toward each colony's rim and is DESATURATED (at 2.1× on a green colony it read as moss, then as a shrub), the core is mottled by the grain so it is not a black ink pool, the grain raises the colonies as a bump for the wet glint to catch, and it all fades back to the plain field once a grain texel is under a few pixels, where a threshold only shimmers. THE END's v3.3 set: `woodTex` is 512² of CONTINUOUS grain — every line one stroke the full height of the canvas on whole sine cycles so it meets itself across the seam (straight dashes read as MDF; no knots, which would stamp themselves down every board on the 0.9m repeat). Book covers come in four bindings — `makeBookCoverTexture` for tooled cloth/leather and `makePrintedCoverTexture` for dust jackets and paperbacks (flat ink, sun-bleached spine, creases on a paperback) — and nearly every spine carries a `callLabel` (class number + author letters), laid out so the spine title never runs into it. `makeArtTexture(size,land)` returns `{tex, land, paint}`: 80% are OIL PAINTINGS OF EMPTY PLACES (a lit reading room with nobody at the tables, a corridor of shut doors, a drained pool, a field with one pole, a stairwell into blue, a yellow-papered doorway, an empty chair, the faceless donor, a nocturne), the rest the documents that earned their place (collection map, the section with one floor too many, the undeveloped staff photograph, the unawarded certificate). The jokes (the HUSH acuity chart, the botanical of HOURS) are gone: a joke on a wall stops being unsettling the second time you read it. A painting is FINISHED by `oilFinish` — brush marks as soft-light strokes that lighten and darken whatever paint is under them without reading the canvas back, a weave, varnish multiplied amber and thicker at the edges, craquelure — and its stroke FLOW must follow the picture: a radial flow put a zoom-blur through the corridor and a vortex through the portrait's head. Canvas size follows sight size (256×320 / 384×480 / 512×640, turned for landscapes). The room's furniture: `texCork`, `texGhost` (the paler rectangle a removed frame leaves, with dust along its top), `texClockFace` (dial only — the hands are geometry, and every clock reads 3:17), `makePlaqueAtlas` (all forty pilaster plates in one atlas so they draw as one), `texExitSign`/`texStaffSign`, `texWetFloor`, `makeCatalogTexture` (sixty drawers with brass label frames, drawn — `CATALOG_COLS/ROWS` place the pulled-out ones), `texPaperSheets` + `PAPER_UV` (four kinds of loose paper on one canvas), and `KB_LAYOUT`, the keyboard's key table that both the printed board and the 3D keycaps read. The shaft: `texShaftMasonry` (eight courses a tile, ONE COURSE PER TREAD'S RISE, so the stair climbs the wall on the coursing; kept dark with a weathered mortar — at the first contrast it was bathroom tile), `texSpoil` (dug earth: a few soft blotches under small low-contrast clods — the first pass was lizard skin) and `texSlabSection` (the floor in section: carpet, underlay, screed, a slab with its rebar cut). `makeFloppyTexture` is 256² with `anisotropy` 8 — a disk lies flat and is read at a grazing angle, the worst case for an isotropic mip chain — and its `top` UV band is mapped the RIGHT WAY UP (v0 < v1). Reversing v to drag the printed shutter onto the end the steel shutter sits on works on the block layout and is fatal to the print: it mirrors the canvas, so every glyph came out upside-down while still running left-to-right, invisible only because 128² had made the lettering an illegible smear. The end-for-end problem is fixed in `makeDisc` instead, by putting the steel on the end the print gives it. `makeTubeTexture(warm)` is THE FILAMENT — the one asset every electric light in the game shares (level-0 troffers and THE END's strips): the canvas HEIGHT is the tube's length (CylinderGeometry's v runs end-to-end), which is what makes END BLACKENING possible, and without the mercury baked onto the glass at the electrodes a tube is just a glowing stick. It must stay bright on average — lights.js drives `tubeMat.color` every frame and this map multiplies it. `texGalv` is the galvanized sheet every fixture shell wears, mapped at a fixed world scale so a 2.2m reflector spine and a 0.09m end cap carry the same steel. `texReflector` is the troffer's painted-steel backplate: like the filament it MULTIPLIES a colour lights.js drives every frame, so it must stay bright on average, and what it buys is SHAPE — a MeshBasic backplate is one flat value, so a trough pressed out of it would look identical to a flat sheet, and the two bright lanes under the lamps (on the THIRDS, v 1/3 and 2/3), the shadow the side walls throw, the dust and the grime runs all have to be printed. It had DEAD FLIES printed on it, legs and all, and from below a scatter of small dark bodies in a lit tray is COCKROACHES — there is no such thing anywhere in this world; what is left is three or four wobbling rust blobs at 0.05–0.12 alpha. `texLouvre` wraps the guard grid's ROD, so u runs AROUND the bar rather than down a face: u=0.25 is the top, facing the lamps 90mm above it, u=0.75 the underside you stand below, and a cosine keeps both canvas edges at the same mid value so the wrap is seamless. Get that inconsistent between the two rod families and half the grid is lit from underneath. `scaleBoxUV` takes an optional `skip` face list for boxes with one FITTED face (a printed label) that must keep its 0–1 mapping while the rest tiles.
- **`scene.js`** — Three.js scene/camera/renderer, the point-light pool, and `buildLevel()` (level 0 geometry; populates the exported `lights` array). Objects present at module init are tagged `userData.persist`; `clearLevelScene()` removes everything else (the level-change teardown; it disposes geometry, textures and a skinned mesh's skeleton — the bone matrices live in a texture — but deliberately NOT materials: disposing a material releases its shader program, three destroys a program with its last material, and every rebuild then recompiled every shader one at a time — most of a respawn. Left to the GC, the program stays linked and the rebuilt level's materials pick it straight up) and resets `lights`/`wallMeshes`/`wallDecals`. `setLevelEnvironment(level)` swaps fog/ambient profiles. `makeLightRecord()` is the single fixture-record factory: every light in the game (level-0 troffer or library hanging strip) is the same self-contained filament asset driven by lights.js — builders only choose the knobs (`bright`/`dimDen` set how yellow a panel idles; `warm`, `flickery`, `fixY`, `wakeAt`). **The point-light loop is patched at module load** (top of scene.js): three unrolls `lights_fragment_begin`'s loop over all thirty pool lights, and every lit pixel evaluated every one of them though each reaches 11m and the unbound ones are dark. It is kept a real loop that skips a light past its `distance` (where three's falloff is exactly zero) or with a black colour, with three's own irradiance maths written out in it (called inside a real loop, its early return makes the D3D compiler warn on every shader) — pixel-identical to three's (verified ≤1/255), roughly half the lighting cost. Transparent layers carry explicit `renderOrder` (`LAYER_SPILL` −2, `LAYER_DECAL` −1, everything floating at 0): the merged decals and the spill sit at the origin, so a depth sort alone put them in front of or behind the entity's aura depending on where you stood. `buildLevel()` uses raw box UVs on the walls and the carpet's original 8m tile; mold decals carry a tight dull wet glint and are grown into SPOTS by `moldCompile` (see `texMoldGrain`). Every lit troffer throws a SPILL onto the tiles around it (`spillMesh`): ONE merged additive mesh, a quad per fixture whose vertex colour is re-read from that fixture's `tubeMat.color` in `onBeforeRender`, so each patch flickers, dies and goes red in the shockwave with its own lamp — the pool lights hang half a metre under the ceiling and only graze it, which left the ceiling beside a burning fixture as dark as the one beside a dead one; the ceiling's own bump stays 0.008 (at 0.012 the fibre relief turned to raised veins); `bumpChunk(dH)` is three's bump chunk with the height derivative supplied by the caller, because the stock one can only read `bumpMap` at the colour map's UVs — the carpet pile, the ceiling foam and the mold grain all need their own. **The ceiling is not a plane.** `ceilingGeometry(SZ,openings)` emits it as a quad grid — one quad a cell, and four border strips around a cut opening in the cells that carry a fixture — with UVs straight from world position so the tiling runs across the joins exactly as the single plane's did, still one draw call. The winding is load-bearing: `(B−A)×(C−A)` has to come out (0,−1,0) or the field faces up into the void and the level has no ceiling at all. The openings exist because the troffer is RECESSED half its depth (`RISE`) into the ceiling: everything above `WALL_H` — the pan, the reflector, both lamps — is otherwise occluded by the very plane it is set into, and the fixture comes out as a dark slot with a grid over it. The fixture SLOTS are therefore chosen at the top of the build, before the ceiling exists, and the ceiling stains, blended in the ceiling's own shader, follow the same openings for free. `batchStatic(root,region)` is the room-wide merge: every static opaque mesh left standing on its own is regrouped by material (per material GROUP for multi-material geometry, winding flipped under a mirror) and merged into one indexed mesh per material, originals removed and their unshared geometry disposed. THE END calls it at the end of `buildLibrary` and it took the room from 1,300–3,300 draw calls to ~240–420 — splitting buckets by `region` to let far corners cull cost more calls than it saved triangles, so it runs with none. It skips anything `persist`, `animated`, `noBatch` or invisible (subtree and all), any transparent or vertex-coloured material, and any material only one mesh wears. ANYTHING THAT IS REMOVED, HIDDEN OR REPAINTED AFTER THE BUILD MUST BE ONE OF THOSE: the carpet plug over the hole shares the floor's material, so it was baked into the floor's batch and `revealHole` removing it did nothing — the hole stayed carpeted from above. It is `noBatch` now. `makeTroffer()` builds the troffer from module-level `markShared`'d geometry (the mirror of library.js's `makeFixture` for the hanging strips) — only the per-fixture glow/tube/rod materials are created per build. THE GRID UNDER THE LAMPS IS ROUND BAR: 16mm rods, 12×6 cells at a 0.22m pitch, and the two families sit one bar-diameter apart in y because a welded grid is welded — at the same height they interpenetrate and every crossing eats a bite out of the run behind it, which came out as visibly DASHED long runs. It was twenty single quads wearing a printed top-to-bottom gradient, i.e. a real egg-crate louvre blade, and 1.4mm of steel seen edge-on is NOTHING: the grid vanished from the one place everybody looks at a ceiling light from, straight up at it, and reappeared as graph paper from anywhere else. All twenty rods still merge to one draw. The housing is `bakeParts`-merged from a pan, four walls, the rim the grid sits in and the TRIM FLANGE (it was six draws — a box with a six-material array). That flange is a RING, never a plate — a plate closes the opening it is trimming: it stays down at the ceiling line while the rest of the fixture rides up, its top sits 1.5mm PROUD of the ceiling plane so the two intersect rather than fight for the same depth, and it is the only thing hiding the 6mm clearance (`OPEN_C`) the opening is cut with. The lampholders are ivory, merged, and are what says the tube is seated in something rather than floating in a box; the two tubes sit on the THIRDS (`TUBE_Z=FD/6`) and merge into one buffer — there was a ballast wireway boxed down the spine between them, which from below is a beam bolted across the middle of the light. 5 draws a fixture, down from 10. The exported `tubeTex`/`warmTubeTex` are the shared filament maps both levels' tubes wear.
- **`props.js`** — collectible/breaker/exit-elevator builders, `placeProps()`, the `interactables` array (+ `clearInteractables`/`addInteractable` for level changes), `updateProps()` idle animation. The three things you are sent to find are real objects: the almond water is a lathe-turned PROFILE (heel, straight side, shoulder, neck, lip — the whole difference between a bottle and a tin can), closed at radius 0 on the base and left open at the lip where the cap covers it, with the liquid as its own inner lathe filled to just under the shoulder (a transparent bottle you can't see a level in is a solid) and a printed label; the fuse is a glazed ceramic cartridge with brass ferrules and FLAT brass blades (flat is the tell that it's a contact and not a peg), and its origin must stay at the base with height ~0.3 because the cutscene flies that exact group into the slot; the breaker is a surface-mounted DISTRIBUTION BOARD fed from the ceiling: a real shell (back, sides, a galvanised pan inside — the old one was a solid slab floating 10cm off the wall; the wall face is at local z −0.15 and the back sits on it), three conduits up the wall into the tiles on straps with a pull box, an instrument band over the door (supply voltmeter on a fitted 0–300V dial, FAULT/MAINS pilot lamps with additive halos, engraved legends laid out off `BAND`), a pressed door on knuckle hinges (rib, folded returns, hooded louvres, a torn DANGER label, a quarter-turn latch, the circuit directory INSIDE the door, where it always is), and behind it a light dead-front (`DEAD`) with two columns of breakers — some tripped, showing their flags — the empty MAIN FUSE holder between them, main lugs and copper straps, a neutral bar, and every conductor running out into open side gutters. The main switch is a red lever on the cabinet's side with a lockout tag on it. Static parts merge per (group, material) bucket; a soft `texBoxShadow` grounds it on the paper, and `makeSparkLines` is ONE `LineSegments` draw that lives in the scene from the build so its program exists before the arc. The cutscene reads everything off `userData`: `doorPivot` (swung about y to `DOOR_OPEN`), `latch`, `fuse` + `FUSE_SEAT` (the fuse's own shared materials — nothing fades, it is carried in), `lever` about x from `LEVER_OFF` to `LEVER_ON`, `tag` (counter-rotated so it hangs), `needle` + `needleAng(volts)`, `lampR`/`lampG` through `setLamp(L,k)`, `trips` (the tripped breakers' pivots and flags), `arc`, `sparks`, and the emit points `socket`/`lugs`/`switchAt`. `setPowered()` puts it in the state the cutscene leaves it in (the debug warp uses it), and `powered` lets `updateProps` keep the needle breathing on the supply. Prop canvases are module-level and `markShared`'d — `placeProps` runs again on every respawn, and teardown disposes anything unmarked, so a rebuilt level would come back wearing dead textures. `makeElevator(p,facing,opts)` takes `{wallH, wallMat}` so THE END reuses it for the crashed arrival cab; `opts.uvTile` maps its odd-sized flank/header boxes at a fixed world scale (THE END), and without it they take raw box UVs like every other wall on level 0. The last word is not a word: `screen.warn(alpha,t)` draws a CRYING FACE on the coarsest grid the glass holds (24×18 cells of 8px, every feature stamped as a mirrored pair about the seam between columns 11 and 12 so it cannot come out lopsided), and `LIB.weeping` keeps the tears running in `updateLibrary` long after the cutscene hands you back — a tear frozen halfway down the glass is a picture, not a face. EVERY FEATURE HAS TO CLEAR THE OUTLINE: the head is only ~7 cells of radius under a one-cell ring, the first pass put an eyelid straight through it, and under the tube's bloom the whole top half fused into one lump with two dark holes in it. And THE STREAK IS THE WHOLE THING — three loose drops under an eye read as noise on a CRT; a standing wet line down each cheek is what makes the face crying rather than merely sad, and the descent's last beat (`startDescentEnd` — the stairs themselves are walkable; main.js fires this only once the player has walked below `STATE.y<−8.5`). It takes the walk off you WITHOUT A CUT: the camera starts exactly where your eyes are (an offset that decays over 0.8s), the bearing is unwrapped onto the lap your feet are on, the angular speed starts at your own tangential speed and eases to a 1.3 m/s walk, the radius eases onto the tread line, the head rides a per-step dip and a footfall lands on every tread boundary crossed, and it looks at the treads ahead rather than into the well. It writes `STATE.pos`/`STATE.y` as it goes so the shaft's depth fog keeps deepening, then hands off to `enterTheNest()` under the black — the descent IS the level transition. THE DIG runs on `LIB.digFx` (particles.js): churn, ground shroud, veil and the breakthrough burst in the dust pool, tinted carpet-grey at first and earth once the dig is through the floor, and the SPOIL COMES OFF THE CLAWS — `spiderDigPose` drives the front two pairs through a four-key scoop (reach, drive down, drag back, flick; left and right half a stroke apart, the second pair a quarter behind) and reports each leg that crosses the flick in `userData.digFlick`, and the cutscene throws clods and dust from that claw (`spiderFootWorld`) out behind the body, with a kick of camera shake. The debris stays on the carpet after the cutscene; the dust mesh is hidden. THE NEST adds its own intro (`startNestIntro` — waking at the stair's foot, craning back up at the silk-wrapped way you came, title card "THE NEST / level 8, wrong side out") and its ending (`startAscentEnd` — main.js fires it only once the player has CLIMBED the open fissure's chimney above `STATE.y>9`: the view spirals on upward while a cold pale — not black — closes in, stone steps and updraft wind carry on, then `win()`). **THE DEATH SEQUENCE** (`DEATH`/`startDeathCam`/`updateDeathCam`/`endDeathCam`) is the same camera language and deliberately NOT a `CINE`: main.js stops updating the world the instant `STATE.dead` is set, so it runs from its own branch outside the play gate — which is exactly right, because the world should be frozen as it was when it caught you and only the view should move. Two causes, two shots: `caught` is the hit, the collapse, the landing (`sfxBodyFall`) and the head turning up to whatever is standing over you — the killer's position is read LIVE every frame from `monster.pos`/`spider.mesh.position`, never captured, so a mesh still posed mid-kill is what you look at, and `lookH` is how far up it to look (2.55 for the wire thing bent over you on level 0, 1.35 for the spider); `fall` has nothing to look at, so the drop simply continues, spinning, into the dark. The closing black is `#deathfx`, an IRIS: a radial gradient whose clear radius `--r` is walked down from 170% to 0. Everything about the dimming is held MILD on purpose (grayscale .55 / brightness .86, dread 0.7) — these floors are already dark, and at the first pass's crush the iris closed on a black circle with nothing inside it. `endDeathCam()` is called from `respawn()` and is the only thing that hands the screen back. While `CINE.active`, main.js skips `updatePlayer`/`updateFocus` and the cutscene owns the camera; `window.NOCLIP_DEBUG` (main.js) exposes hooks for smoke tests, and hidden debug chords exist: triple-[6] warps to the level-0 endgame, triple-[7] drops into THE END (or, already there, pockets every remaining disk), triple-[8] warps to the terminal with every disk pocketed, triple-[9] drops into THE NEST with the lantern (or, already there, burns the brood down to one and stands you at the survivor).
- **`lifecycle.js`** — `prewarmLevel0` (fired from main.js once the start screen has painted: builds level 0, holds it OFF the scene — the menu draws over an empty one — and compiles its programs and uploads its textures a root at a time between frames, with dark stand-in PointLights for the lights outside the root being compiled, because the light count is part of every program; DESCEND went from a ~2s freeze to one ordinary frame), `startGame` (takes the prewarmed level if there is one), `enterTheEnd` (teardown + library build + intro), `enterTheNest` (teardown + cave build + intro; swaps the keys hint for the lantern controls), `respawn` (level-aware: THE END respawns at the wreck keeping disks; THE NEST respawns at the dead stair keeping the lantern and every burn), `die(cause)`/`win` (level-aware copy + stats — and in THE NEST both call `hushCave()` + `silenceHatchlings()`, because main.js stops calling `updateCave`/`updateHatchlings` the instant you die and every loop the level is holding open would otherwise freeze at its last gain and drone under the death screen), debug warps. **`die` no longer paints the screen and opens a menu in the same frame**: it hands the camera to `startDeathCam` (cutscene.js) and passes `showDeathCard` as the callback the sequence fires ~2.8s later, so what the card says stays here, where the state is. It also tears down any live cinematic first — one `updateCinematic(0)` call takes that function's own dead/won branch, which main.js can never reach again once `STATE.dead` is set, and without it the breaker scene resumed after the respawn. The card is SPECIFIC (who caught you, what you KEEP, time on this floor, and a rotating floor-appropriate tip) because "you died, try again" is the one thing the player already knows. `win()` treats THE NEST as the END OF THE GAME, not a third level card: `winOverlay.finale` swaps the sheet to a cold pale, shows the RUN COMPLETE badge, breaks the time down per floor, and says in plain words that there is nothing above the fissure yet — the level cards for 0 and 1 are fallbacks and read as transitions.
- **`ui.js`** — DOM refs (`ui`), `toast`, objectives HUD (level-aware), overlay/pause logic, pointer lock, settings persistence (key + reader live in `settings.js`), mixer wiring. `setLevelChrome(level)` swaps `body.lvl0/1/2`, which is the ONE place the interface's colour is decided: main.css derives every HUD panel, menu, button and key hint from an `--accent` family, so a floor's palette (backrooms yellow · the library's dead blue-grey · the cave's fungus teal) costs one class change and cannot drift between elements. **The objectives log is a data model, not markup** — `objRows()` returns `{txt,done,active,have,total,guide}` per level and the renderer decides how to draw a count: PIPS while the total is small enough to read at a glance, a METER once it isn't (the disk hunt runs to twenty-odd, and twenty-two pips in a HUD corner is a barcode). A redraw is gated on a signature of that model, because the log is rebuilt every second and a full `innerHTML` swap per tick is what made a "new objective" flash impossible to detect. The BEARING row is the exception that is refreshed every tick: it reads `STATE.guide` — the only pointer the HUD is ever allowed to carry, set exclusively by `revealHole()`/`openFissure()` when a cutscene has already SHOWN you the way out, never for a collectible — and its arrow comes from the same forward basis (`−sin yaw, −cos yaw`) as player.js and the cutscenes, so a mirrored arrow is impossible by construction. How to Play is TABBED (`syncGuide`/`showPane`) and a floor you have not reached keeps its pane `sealed`: the guide can name THE END and THE NEST without spoiling either, because the naming is gated on `STATE.level`.
- **`input.js`** — keyboard/mouse/pointer-lock listeners (side-effect module).
- **`main.js`** — imports everything and runs the `requestAnimationFrame` loop; dispatches `updateMonster` vs `updateSpider`+`updateLibrary` vs `updateSpiderCave`+`updateHatchlings`+`updateCave` on `STATE.level`; `updateLantern` and the descent/ascent cinematic triggers run here too.

THREE is a global (classic CDN `<script>` loads before the module graph) — modules do not import it.

There are intentional function-level circular imports (`monster ↔ lifecycle`, `ui ↔ lifecycle`, `cutscene ↔ lifecycle`, `spider ↔ lifecycle`, `library → ui → lifecycle → library`, `cave ↔ lifecycle`, `cave → ui → lifecycle → cave`, `spider → cave`/`spider → hatchling` one-way); they are safe because nothing in the cycle is called during module evaluation. Don't add top-level calls across these boundaries.

## Key conventions

- The map coordinate system uses `cellToWorld` / `worldToCell` (level 0), `cellToWorld2` / `worldToCell2` (THE END) and `cellToWorld3` / `worldToCell3` (THE NEST) to convert between grid cells (integers) and Three.js world space (meters). `CELL` (4m) is shared by all three.
- `MeshPhongMaterial` is used deliberately over `MeshLambertMaterial` on large floor/ceiling planes — Lambert is per-vertex in Three.js r128, which produces all-or-nothing lighting on geometry with only corner vertices.
- **Nothing UNIQUE may live in a tiling map.** A one-off feature drawn into a texture that repeats becomes that feature repeating on the tile pitch, which reads louder than whatever it bought — a single lifted wallpaper seam turned into an identical lifted seam every 2m down every corridor in level 0. One-off damage goes on a decal (the mold/drip system is exactly that); a tiling map may only carry what is true everywhere.
- **A texture's resolution is px/m, not canvas size**, and the two are only related through the UV rate. Every generator in this codebase has been rewritten at least once for the same reason: features drawn below the size the eye resolves at the distance you view them from average straight back out to the flat field they started on. Check px/m before adding detail.
- **LEVEL 0's tiling surfaces are deliberately plain, and the restraint IS the atmosphere.** The wall, the carpet and both stain overlays were rebuilt at 4× resolution with drops, seams, batch tones, berber flecks, tide rings, bump maps and printed grime. Every single one of those upgrades shipped as a defect — veneered plywood, ceramic tile, crop circles on the floor — and all of them have been reverted to the originals. What finally stuck kept every DESIGN exactly and raised only the resolution and the MATERIAL — a print too faint to name from across a room, paper grain — and that is the only kind of upgrade these maps take. A surface you walk past for twenty minutes at a 4m repeat cannot carry a FEATURE: anything nameable on it becomes the thing you see, everywhere, at once. Detail on this floor goes on the decals (unique per instance) and on objects (props, fixtures), never into the tiling maps. The ceiling is the exception that proves the rule — what it got was not features but MATERIAL (`ceilFace`).
- **Nothing organic may have a straight edge.** Damp, grime, mold, spills and stains drawn as `fillRect` put four visible corners on every mark — a wall covered in faint hard-edged rectangles stops being stained and becomes veneer with printing on it, which is exactly how level 0's rebuilt wallpaper shipped. Use gradients or paths. The same applies at a decal's own border: the instant anything inside it still has alpha at the canvas edge you see the decal's RECTANGLE, however soft the art is (THE NEST's `silkFeather` is the surviving example of the fix).
- **ALPHA IS THREAD-SHAPED, and it is not only silk.** THE END's plastic wrap was a box at 0.18 opacity wearing a flat blue-grey — a CUBE OF FOG, a solid you can see a little way into, with six hard corners and not one fold. What makes film read as film is never the tint: it is the CREASES, so the map carries strokes and nothing else. The first rewrite still laid down nine broad soft blooms "where the sheet lies doubled", and a 60px radial gradient at 0.12 alpha is not a fold, it is a milky PATCH — it came out as a glowing oval floating over the object inside. Same rule, same reason, as THE NEST's `silkFeather`: no broad translucent fills anywhere.
- **A CRUMPLED SURFACE IS FACETS, and `flatShading` is worth as much as the geometry.** A smooth-shaded shell of a crumpled silhouette is a BELL JAR — which is exactly what the wrap came out as until its material went flat-shaded and its mesh went COARSE (20×14, not 32×20: with flat shading the panel count IS the fold count). The folds that matter are the LOW harmonics, because what reads as crumpled is the SILHOUETTE — amplitude spent on k=5 and 7 is surface ripple you cannot see against the room. And a fold field that barely drifts with height runs every ridge the full height of the bag and comes out FLUTED, like a column.
- **EVERYTHING ON A WALL READS ONE LEDGER.** THE END used to dress its walls in four blind passes (texts, posters, the hang, cracks) off a cycling cursor; once they wanted more faces than the room had, the cursor wrapped and the last pass came down on top of pictures already hanging. `dressWalls` books every piece — frames, ghosts, noticeboards, clocks, lettering, cracks — as (s, y, w, h) in a per-wall ledger and checks it first, and the elevator is booked before anything else. A keep-out written into the ledger is the one a pass added later cannot fail to see.
- **A SPACING CHECK MUST NOT BE WIDER THAN THE SPACING IT VALIDATES.** The old salon hang laid its clusters out with a 0.10–0.19m gap and then rejected any piece within 0.22m of a neighbour — so every second picture failed, silently, and a 34-piece hang shipped as a 10-piece one. Nothing about it looked broken; only counting the placed objects found it. The ledger's margin (0.06) is below the tightest spacing the bay layouts use.
- **PRINT AND HARDWARE READ ONE TABLE.** `COP` and `HALL` in props.js are shared layout objects: the faceplate box, the engraved canvas and the button meshes all derive from the same numbers, so an engraved numeral cannot drift off the button it belongs to and an arrow cannot end up behind one. Same rule that put the vintage PC's vents back onto the surfaces they sit on.
- **A REGULAR GRID DRAWN INTO A FLOOR OR WALL MAP IS TILE.** It has happened three times — the library's carpet, level 0's carpet (in the diffuse map *and* embossed in the bump map), and level 0's wall. A lattice at any real contrast is grout; a tuft grid at 128 px/m is a 3cm mosaic; a full-width rule every 4px is lumber. Textiles are a SCATTER with a broad metre-scale mottle under them, and paper is nearly featureless.
- **THE HUD POINTS AT EXACTLY ONE THING, AND ONLY AFTER A CUTSCENE HAS SHOWN IT TO YOU.** `STATE.guide` carries a bearing to a way OUT the level has already revealed on camera — the library's dug hole, the cave's opened fissure — and nothing else may ever set it. Both are the *last* objective on a floor that is 130m/188m across, announced by a toast and then never mentioned again, which is a sweep, not a search. A collectible is different in kind: finding the almond water, the disks and the corpse IS the level, and an arrow pointing at any of them deletes it.
- **A SUSTAINED GAIN MAY ONLY BE WRITTEN BY A FRAME THE WORLD IS STILL RUNNING IN.** `die()` closes every loop the level is holding open — the entity's proximity bed and breathing, the librarian's skitter bed, the cave's fires and stream (`hushCave`) — but the function that CALLED it carries on to the bottom of its own frame, and main.js never runs another one: whatever those frames wrote after the kill was the last value the gain ever received, and it held forever, under the death card, under the menu and straight through the respawn. All three hunters kill from the middle of their update, so every continuous-audio block is gated on `!STATE.dead`, and `updateCave` — which main.js still has queued BEHIND `updateSpiderCave` in the very frame she catches you, and which kills you itself on the fall — returns outright. One-shots are exempt; they end on their own.
- **UI TEXT IS PLAIN.** Menus, prompts, objectives, toasts, death and win cards and level title cards say what they mean in ordinary words ("You were caught", "Insert 3 disks", "How to Play"). The atmosphere lives in the world — the wall lettering, the posters, the paintings — not in the interface; the v3.1 copy ("THE HUM CONTINUES WITHOUT YOU", "SILENCE IS A CURRENCY — YOU OVERSPENT") read as the game performing at the player. Options carries labels only; anything a control's label cannot say goes in its `title`.
- **`mergeStatic` ends in `freezeStatic`**, so a `.position.set` on its result writes a matrix that is never recomposed and the mesh silently renders at its parent's origin. Bake placement into the source meshes before merging, or re-enable `matrixAutoUpdate` deliberately (spider.js's abdomen does the latter).
- Light pool pattern: `LIGHT_POOL_N` point lights are reused each frame, bound to the nearest fixtures within `LIGHT_BIND_RADIUS`, instead of one light per fixture. All levels' fixtures share the same `lights`-record shape (library records add `fixY`/`wakeAt`; cave records add `cold`/`buzz:false`/`mul2`/`region`). `cold` records KEEP the idle breathe (it is the intended slow pulse) but never enter a flicker BURST: `canBurst` is gated on `!L.cold`. Strobing is a failing ballast, and a mushroom has not got one — the bursts were inherited from the electric floors and read as wrong on a plant. Fungus reacts only through `mul2`, the region die-back when a brood burns.
- Never change the scene's light COUNT at runtime — three.js r128 keys shader programs on it and recompiles everything in one frame (a hard hitch). Reveal-later lights (the library's hole, the cave's fissure and clutch fires, the lantern, the elevator ride's emergency light and spark glow) are all created up front at intensity 0 and pre-warmed with `renderer.compile`. Every lit program costs 35–60ms to compile on ANGLE/D3D and three r128 compiles them strictly one after another (it queries each program's uniforms the moment it links, so the driver's parallel compile never gets a queue), which is why level 0 is built and warmed behind the start screen (`prewarmLevel0`) and why programs are kept across rebuilds.
- Exported `let` bindings (`grid`, `grid2`, `grid3`, `exitDoor`, `lights`, `interactables`) are reassigned/mutated by their owning module; importers see live values but must not assign to them. All three grids are on `window.NOCLIP_DEBUG` (along with `W`/`H`/`CELL`/`cellToWorld`) for smoke tests.
- THE END's grid cell codes: 0 open · 1 wall · 2/3 shelf (along x/z) · 4 table · 5 desk. The spider treats every nonzero cell as solid; players pass type-4 cells only while crouched.
- THE NEST's grid cell codes: 0 open · 1 rock · 2 squeeze · 3 stream · 4 scree · 5 void · 6 bridge · 7 rubble. The matriarch treats 1/2/5/7 as solid; hatchlings pass squeezes (1/5/7 solid); players pass 2 only crouched and fall through 5.
