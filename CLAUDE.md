# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A first-person browser horror game — "NOCLIP: Escape the Backrooms" — vibe-coded with Claude Fable 5 / Claude Mythos 5. Vanilla JS ES modules with Three.js r128 from CDN; no build system, no package manager, no compilation, no image or audio assets (everything is procedurally generated).

Three levels as of v3.0.0: **LEVEL 0** (the yellow backrooms maze), **THE END** (the infinite library, entered when the exit elevator's brakes fail) and **THE NEST** (the fungus-lit cave below the library's dug stair). `STATE.level` (0/1/2) picks the active update path; the renderer, light pool, audio buses, interaction/focus, HUD and cutscene systems are shared across levels. Versioning: major = number of levels, minor = refinements to existing levels. Per-level lore documents (menu wiki entry + in-world found document, parse-ready) live in `lore/` — see `lore/README.md` for the format contract.

## Running locally

The game uses ES modules, so it must be served over HTTP (opening `index.html` via `file://` will not work):

```
npx serve .
# or
python -m http.server
```

GitHub Pages serves `index.html` at the repo root as the live site.

## Architecture

`index.html` is markup only (HUD + overlay screens); `css/main.css` holds all styling; game code lives in ES modules under `js/`, entry point `js/main.js`:

- **`utils.js`** — `$`, `clamp`, `lerp`, `angLerp`, `rand`, `hash` (the shared sin-fract noise used by flicker/cutscene/blackout jitter), and `srand` (seeded RNG used only by map gen, so layouts are reproducible).
- **`settings.js`** — `SETTINGS_KEY` + `readSettings()`: the one reader of the persisted settings blob. Exists because scene.js needs the saved graphics quality at renderer construction (antialias is fixed at GL-context creation), long before ui.js evaluates.
- **`state.js`** — the flat mutable `STATE` object (player + progression for all levels; THE NEST adds `hasLantern`/`lanternOn`/`lanternCharge`/`cranking`, `clutchesLit`, `frenzyT`, `caveT0`), `KEYS` (raw input), the `monster` state object (level 0), and the `spider` state object (THE END + THE NEST — the same individual). Everything reads/mutates these shared objects.
- **`map.js`** — level-0 grid constants (`W`, `H`, `CELL`, `WALL_H`), random-walk carve in `genMap()`, `cellToWorld`/`worldToCell` conversions, `isWall`, `losCells` (line of sight), `bfsPath` (entity pathfinding). `CELL` is shared by both levels.
- **`textures.js`** — `makeCanvas` + procedural textures via 2D canvas: level-0 wall/carpet/stain/ceiling, mold/drip decal growers, THE END's set (`texLib*`, woods, `makeCrackTexture`, `makeEndTextTexture`, `makePosterTexture`), THE NEST's rock/floor/dripstone + the silk family, and the shared spider chitin maps (`texSpiderAbd`/`texSpiderCarapace`/`texSpiderLimb`), THE NEST's `texEggSac`/`makeFlameTexture`/`texCocoon`. The two lathe-dressing maps have an ORIENTATION CONTRACT: u wraps the body, v runs front→rear, so a horizontal stroke becomes a RING — the carapace's striae must be drawn as VERTICAL strokes or the head reads as a cut tree stump, which is what the first pass shipped. All the chitin maps are kept near-neutral: warm browns times the lantern's orange multiply out to BRONZE, and the spider looked cast rather than grown. `texCaveRock` is 512² because the walls are UV'd at 4m/tile — at 256 a facet you stand beside was a smooth gradient. It is built from multi-scale blotching plus SHORT angular joints drawn wrapped: never long smooth curves, which tile into visible worms crawling across every wall. `texCaveFloor` follows the same lesson at ground level — sediment lobes, runoff channels, drying cracks and proud stones with lit crowns, all MID-scale, because the old floor was 9000 sub-pixel dots that averaged to flat brown and gave the bump map nothing to bite.
- **`scene.js`** — Three.js scene/camera/renderer, the point-light pool, and `buildLevel()` (level 0 geometry; populates the exported `lights` array). Objects present at module init are tagged `userData.persist`; `clearLevelScene()` removes everything else (the level-change teardown) and resets `lights`/`wallMeshes`/`wallDecals`. `setLevelEnvironment(level)` swaps fog/ambient profiles. `makeLightRecord()` is the single fixture-record factory: every light in the game (level-0 troffer or library hanging strip) is the same self-contained filament asset driven by lights.js — builders only choose the knobs (`bright`/`dimDen` set how yellow a panel idles; `warm`, `flickery`, `fixY`, `wakeAt`). `makeTroffer()` builds the level-0 troffer shell from module-level `markShared`'d assets (the mirror of library.js's `makeFixture` for the hanging strips) — only the per-fixture glow/tube materials are created per build.
- **`props.js`** — collectible/breaker/exit-elevator builders, `placeProps()`, the `interactables` array (+ `clearInteractables`/`addInteractable` for level changes), `updateProps()` idle animation. `makeElevator(p,facing,opts)` takes `{wallH, wallMat}` so THE END reuses it for the crashed arrival cab. The elevator is carved into its wall cell (the wall box mesh is removed and rebuilt as flanks + header around a recessed cab; the grid cell stays solid for collision).
- **`library.js`** — THE END: `grid2` gen (one vast room; perimeter walls, shelf runs that converge/anchor into walls, table islands, the central 3-cell desk), connectivity repair, type-aware queries (`libCollide` — tables passable only while crouched, plus circle obstacles in `LIB.obstacles` for chairs/lecterns/ladders; `losCells2` — shelves block sight, tables/desk don't; best-effort `bfsPath2` that routes to the nearest standable cell when the target is unreachable; `cellAt` for the spider's leg-terrain probe), `buildLibrary()` (geometry — wall boxes get world-scaled UVs via `scaleBoxUV` so the tileable plaster never distorts; hanging fixtures pushed into `lights`; furniture, readable-nonsense posters, cracks, wall texts, vintage PCs, 16–22 floppy disks, the terminal), the way down (`buildHole` — the carpet is a `ShapeGeometry` cast with a circular hole two cells behind the desk, covered by a UV-matched carpet plug; beneath it a stone shaft, one merged spiral stair, stacked blue glow/fog discs and idle-at-zero blue point lights, all invisible until the terminal ending calls `revealHole()`; the shaft's point lights live in the scene awake-but-dark from build — revealing them inside the group would change the light count and force a full shader recompile mid-cutscene — and `buildLibrary` ends with a `renderer.compile` pre-warm pass over the hidden group for the same reason; the dig zone is excluded from prop placement via `clearOf`, and `LIB.hole` carries `{x,z,r,stair}` for the cutscenes and physics). The open stair is walkable: `libGroundY(x,z,curY)` returns the tread height under a point (lap disambiguated by the player's own height), `shaftClamp` is the below-floor wall, and `updateLibrary` densifies/blues the fog as a pure function of `-STATE.y`, and `updateLibrary()` (the 125s post-first-pickup light drop, temporary whole-floor blackouts, decor-PC boot-and-die animations, the open hole's breathing glow). Shelf visual segments are DERIVED from the final grid after repair, so collision and graphics cannot drift apart.
- **`cave.js`** — THE NEST: `grid3` gen (chamber blobs + winding tunnels; cell codes 0 open · 1 rock · 2 squeeze (crouch-only, matriarch-blocked) · 3 stream (noise-masking wade) · 4 scree (1.6× noise) · 5 void (the chasm) · 6 bridge · 7 rubble (sealed alt tunnels)), connectivity repair for BOTH the crouched player and the squeeze-blocked matriarch, and the ORGANIC TERRAIN FIELDS — the load-bearing idea of the level's geometry: `floorYAt`/`ceilYAt`/`wallField` are deterministic functions of world position (corner-grid bilinear + sine detail; `wallField` is a lateral 3D vector field, zero at the floor line, ≤0.26m through the body band so the camera can never clip, swelling to overhangs near the vault) sampled per vertex by the meshes AND queried by gameplay/placement, so geometry and collision/anchors cannot drift apart. Floor: rolling ±0.5m corner noise damped DEAD FLAT where gameplay stands on the numbers (stream bed −0.25, bridge/chasm lips/squeezes 0, spawn+corpse, brood pads, fissure alcove — `fW` weights). Ceiling: corner min of adjacent cells' heights + jitter, with the hard clamp: any corner touching a standable cell ≥3.95m and `ceilYAt ≥ floorYAt+3.62` — the vault NEVER dips below 2× player height over walkable ground (a build-time audit console.warns if a future edit breaks this); squeeze cells close to a ~1.5m bore past a mouth ramp that lives INSIDE the squeeze cell (`de` edge-distance lerp — an upright head never meets stone; squeeze-adjacent floors are locked flat so the two ceilYAt branches agree at the boundary). Walls are displaced faceted sheets per exposed rock face (floor-welded, vault-welded, corner-continuous because vertices are functions of world position alone — no boxes anywhere). THE WELD IS A TESSELLATION CONTRACT, not just a shared field: a wall face's COLS must equal the sub-quad count of the floor AND vault over its own cell (3, or 4 in a squeeze — the floor matches that too), and ROWS is the GLOBAL `WALL_ROWS`, never per-face. Sampling the same edge curve at different intervals makes the two polylines drift apart between shared points and opens slivers you can see the void through; a per-face ROWS did the same to any column shared by two faces. A build-time weld audit is easy to redo: every wall vertex at the floor or ceiling line must coincide EXACTLY with a floor/ceiling vertex. ceiling 3×3 (squeeze 4×4) faceted sub-quads; the floor is 3×3 sub-quads too but SMOOTH-shaded from `floorNormalAt` (the height field's own gradient, sampled at build time) — fractured rock reads as planes, sediment must not. Scale: 47×47 grid, 2-cell (8m) wide spokes carved by `carveTunnel(…,wide)` with 3-wide bulges, tunnels 4.8–6.6m tall, central chamber r 6.5 cells under an 18m dome, broods r 4–4.5 under 12–13m, squeezes are 3×3 stamps across the full loop cross-section; the fissure pocket's cell is skipped so its bore stays open; entity meshes (matriarch, hatchlings) and every prop ride `floorYAt`, and `CAVE.approachC`/`CAVE.bridgeC` carry the fissure-approach/bridge cells for rockfall's protect marks (no hardcoded coordinates). Type-aware queries (`caveCollide`, `underRock`, `losCells3`, best-effort `bfsPath3(…,small)` — `small` walks the hatchlings' grid, `cellAt3`, `surfaceAt`/`surfaceNoiseGain`/`silkGainAt`), `buildCave()` (fungus colonies as **cold** light records — no buzz, `mul2` region dimming, per-colony `tint`/`poolCol` driven by lights.js; the mushrooms themselves are lathe-built varieties UV-mapped into a shared skin atlas (`makeFungusSkin` — diffuse + emissive strips for stem/gills/cap/bulb): wall conks (per-colony size class `sf` 2–10× on a skewed power law — the metre-plus ancients mount ABOVE head height and low ones >0.5m radius push obstacles), floor toadstool families, stream-bank finger coral, scree puffballs, chosen per cell code/chamber/water proximity, blushing violet within 5 cells of a brood; every colony grows 2–4 mycelium CORD ribbons (`cordGeo` — thin tapering strips that follow the displaced surface point by point, UV'd into the glowing bulb strip; glowMat is DoubleSide for them) instead of the old flat vein decal — wall colonies keep NO decal at all, floor colonies keep one small dim ground halo; each colony is one merged mesh (+ floor halo) ≤2 draws; dripstone is lathe-grown, never conical — `spireGeo`/`columnGeo`/`stumpGeo`/`moundGeo`/`curtainGeo` build drip-ringed, per-point-jittered profiles that `dripNoise` pushes out of rotational symmetry (radial noise + a slow lean), skinned by `texDripstone` (pale streaked calcite, its own bump map) on `wetMat`/DoubleSide `curtainMat`; varieties by location — chamber spire stacks on flowstone mounds with answering hangers, full floor-to-vault waisted columns (obstacle r 0.55), wall drapery curtains hung from the wall face's own edge-corner vault, flowstone cascades on stream banks, snapped stumps + toppled spires in the scree, soda-straw clusters around ceiling seeps — all merged into three meshes (floor/ceiling/curtains); webs are 3D silk STRUCTURES, never flat wall decals — `webSheetGeo` (sagging pinned sheet), `webHammockGeo`, `funnelWebGeo`, `webWrapGeo`, `webStreamerGeo`, `strandMesh` (a thin quad strung point-to-point; guy-lines) on a lit Phong silk material family (glistens under the lantern; textures.js's `makeWebSheetTexture(torn)`/`makeCobwebTexture` (top-edge anchored fan)/`makeStrandTexture`/`makeFunnelTexture`). The silk maps obey one rule: ALPHA IS THREAD-SHAPED — no broad translucent fills anywhere, and the sheets feather out at their border (`silkFeather`) so a quad's rectangle never shows as an edge. Break that and sheets go back to reading as panes of dirty glass hanging in the air. They are mipmapped (POT, anisotropy 4) so distant silk softens to haze instead of aliasing into scratches. Anything hung FREE from the vault uses `webVeilGeo` (pinned along its top edge only, so it tapers and sags), never `webSheetGeo` — a four-sides-pinned sheet hung loose reads as a flat billboard floating in mid-air. Every ceiling-hung web is sized against the LOCAL floor-to-vault room, never an absolute height: a web that reaches the ground stops reading as silk and starts reading as a wall. Slung sheets hang within 0.45m of the vault AND carry four corner guy-lines up to it — slung lower with nothing visibly holding them, they read as sheets floating under a ceiling that isn't there; placement by junction type — corner sheets strung across the chord where two wall faces meet, wall-ceiling fans pinned along the face's edge-corner vault (order `YXZ`, yaw then tilt), floor skirts + funnel retreats at the wall base, hammocks on 4 real guy-lines, streamers thickest in low tunnels, torn veils + loose strands choking squeeze mouths (their own scan — the solid-neighbor loop skips code 2), rare silk wraps + stakes on brood-side stalagmites (found via `CAVE.obstacles` r 0.45/0.55), a layered hammock CANOPY directly over each brood, a per-chamber DOME RIGGING pass (`c.r²·2.1·density` slung sheets / hanging veils / long streamers / vault-to-vault lines — the den reads from the ceiling), and the arrival mouth silked shut; density = brood proximity (radius 16 cells, floor 0.12); merged into 7 draws (2 sheet + 2 fan + torn + strands + funnels); the ARRIVAL SHAFT — `CAVE.stairMouth` `{x,z,rCut,lip}` is fixed right after `genCave()` so the vault pass cuts a round mouth around it (sub-quads whose center is within `rCut`) and every ceiling-hung placement (`inMouth`) keeps clear; The fissure's chimney is walkable: `caveGroundY` is the library stair's lap-disambiguation math inverted (treads rise), `caveShaftClamp` is the bore wall above the alcove ceiling.
- **`hatchling.js`** — THE NEST's brood: 5–6 cat-sized, eyeless, photophobic mini-spiders (`HATCH`), one per brood chamber plus tunnel wanderers. Territorial leash + sound pursuit (no BFS — slide-along-cells steering); the lantern beam (`inBeam`) and clutch fires physically repel them; one that reaches you **latches** (mesh rides the camera shoulder, stamina bleeds at 0.30/s — faster than rest regen — and a screech loop feeds `spider.lastKnown` every frame) until shaken off (accumulated |Δyaw| > 5.5) or burned off (lantern on ≥1.1s), then 16s of cooldown. Frenzy (`STATE.frenzyT>0`) doubles their hearing, +40% speed, drops the leash. At range their taps are tuned to read as dripwater.
- **`lantern.js`** — the crank lantern: `toggleLantern()` ([F]), `updateLantern()` (charge drain ≈95s, crank recharge ≈22s while holding [R] — loud, speed-capped, `STATE.cranking` is a hearing event for both AIs), `inBeam()` (an AOE radius+LOS test, r 9 — despite the legacy name there is no cone), HUD charge bar classes. It is a LANTERN, not a flashlight: the dominant light is a warm orange PointLight pool centred on the hands (plus a very wide soft SpotLight forward wash — no cone edge), and its intensity breathes on slow incommensurate sine + hash noise like a real mantle, guttering hard only below 18% charge. Both lights are created at module init and live in the scene from the first frame at intensity 0 — the light count never changes, so toggling can never trigger a shader recompile.
- **`spider.js`** — THE END's librarian: horse-sized spider mesh with a procedural 8-leg gait, and the hearing-driven AI in `updateSpider()`. The mesh is anatomical, not primitives: abdomen and carapace are LATHES turned onto the body axis (`bodyLathe`, u around the body with u=0.5 dorsal, v front→rear) so `texSpiderAbd`'s folium and `texSpiderCarapace`'s striae land correctly; 8 eyes in two rows, chelicerae, pedipalps, and legs with a tarsus/claw and bristles. Everything below `femG` is rigid (tibG's rotation is fixed at build), so each leg MERGES to one draw — 12 draws total vs 34 before. Every body lathe CLOSES at both poles (profile radius 0.001 at t=0 and t=1) — a profile starting at a non-zero radius leaves an open ring, and with backfaces culled you see straight through it, which is what put a hole in the middle of the face. Eyes are seated on the shell by projecting their offset onto the carapace ellipse at their own z (`carRadiusAt`) rather than by hand-picked xyz, which buried the laterals inside the skin; they are flattened lenses aimed along the surface normal. Head parts are placed by a POINT and a DIRECTION (`aim`/`end`/`spike`/`seg`), never by Euler angles — hand-written rotations are how the chelicerae ended up inverted (tip welded to the face, fat base swinging free) and the pedipalps buried in the carapace; `spike`/`seg` build from the attachment outward along +Y and then aim +Y, so a part cannot come out inside-out. The animation contract the gait depends on is `userData` `{legs[{hip,femG,basePhi,phase,front,row,fold}], eyeMat, abd, head, BODY_Y, scratchAnim, sniffAnim, abdTilt}`; `abd.scale` is overwritten every frame to (1, 0.9, 1.35) and `TAIL_LOCAL` assumes the abdomen's rear sits at local z −0.8, so it cannot be resized without moving both. THE NEST reuses the same mesh/gait with a separate state machine in `updateSpiderCave()` (tend/tending patrol between unburned clutches · seek/investigate/chase · frenzy→rampage on `CAVE.lastBurn` · permanent `hunt` once all four burn): hearing = 0.8× dulled in open cave, ×2 through silk-laced nest floors (`silkGainAt` at the PLAYER's cell), scree/stream surface gains, cranking heard flat at 18m, sustained lantern light (>5s, LOS, <40m) steers it in, a latched hatchling feeds it your position continuously; squeezes are its table-cells (impassable, sight-blocking, kill-proof). `resetSpiderCave` re-seeds its rounds. Disc pickups alert it after a flat 1s reaction (a pickup beyond 45% of the room span sends it on a wall/ceiling transit instead of a floor seek); stacked pickups before it starts moving cut the countdown by 1s each and add +0.25× speed; pickups while it's en route retarget it and add +0.25× (run base 7.28 m/s = 1.4× its browse pace, cap 2×). Uncrouched movement alerts it strongly within ~16.5–17m / mildly out to ~25m (base radii 13.6/20.4 × movement & surface gains); crouched movement is silent. It cannot enter table cells — a hidden player gets a circling `stalk` that times out. The table keep-out (`pushFromTables`) must stay inside the table's cell (margin ≤0.45); because that keep-out holds the body at exactly 2.0m from a table centre, seek arrival has a wider 3.2m radius for heard spots ON a table (the 2.0m close-approach can never fire there), and the anti-deadlock watchdog drops any path it can't physically close — escalating a pinned seek within 6m of its spot straight to `investigate` so a search episode always terminates.
- **`audio.js`** — `AU` bus object and all Web Audio synthesis: `audioInit()` (buses, hum, drone, breathing, ambient interval layers — the interval layers are gated to level 0), one-shot `sfx*` functions, `panTo` (world position → stereo pan). THE END adds `startLibraryAmbience()` (faint rumble + the spider's proximity skitter bed), `escalateLibraryAmbience()` (post-drop harmonized subs + far thunder), spider/disc/terminal one-shots, and a `muted` footstep variant for the thick carpet.
- **`monster.js`** — level-0 entity mesh, wander/investigate/alert/chase/hunt state machine in `updateMonster()`, sight/hearing checks, wall-knocking, proximity audio. Every recurring disruption shockwave (not the wake one) hands it the player's position; it also space-folds ~every 13s (−2s per objective, floor 7s) 2–4 wall segments along its current path — fog/shear-line poofs at both ends plus a muted `sfxTeleport`.
- **`player.js`** — `updatePlayer()`: movement, sprint/stamina, jump physics, AABB collision (level-aware: `libCollide` in THE END, `caveCollide` in THE NEST; uncrouching is blocked under a tabletop or a squeeze), camera/head-bob, the post-drop micro screen shake (`STATE.shakeAmp`), footsteps. Ground height is level-aware: THE END's stair (`libGroundY`/`shaftClamp`) descends, THE NEST's chimney (`caveGroundY`/`caveShaftClamp`) ascends, the stream is a −0.14m wade and the chasm returns −999. Cave footsteps pick a voice per `surfaceAt` (stone/water/scree); cranking caps speed at 2.4 m/s; wading drags −20%. Once the breaker is fixed (`STATE.powerOn`, level 0 only), adrenaline: bottomless stamina shown as a blue ADRENALINE bar, +20% sprint speed (9.6 m/s).
- **`lights.js`** — `updateLights()`: event-driven flicker bursts (proximity of the level's hunter triggers them — flicker is the radar on every floor; level 0 keys on the monster, 1–2 on the spider), light-pool binding (per-fixture `fixY` height), positional buzz binding (records with `buzz:false` — the fungus — stay silent), THE END's wake-wave gate (`STATE.libWakeT`), the 75%-dim + warm shift (`STATE.libDim`), blackouts (`STATE.libBlackout`), and THE NEST's `cold` records (per-colony `tint` drives the emissive color — components may exceed 1 because the fungus emissive MAP averages under white — and `poolCol` colors the bound pool light; no warmth pipeline, no ballast ticks; `mul2` applies the per-region fungus die-back).

- **`cutscene.js`** — `CINE` state + the scripted cinematics: the breaker fuse animation (entity rushes the panel at chase speed, freezes at a 30m ring until control returns), the exit-elevator escape/brake-failure ride (its end calls `enterTheEnd()` — the crash IS the level transition), THE END's intro (waking in the wrecked cab, doors grinding open in two tries, the fixture wake-wave, title card), the terminal ending (boot → "THE END" → static → the camera cranes up to an aerial seat chosen at runtime for clearance from the random fixture canopy → the spider sprints in and digs itself under behind the desk inside a brown/blue dust shroud, `revealHole()` swapping the carpet plug for the open shaft at peak dust → crane back into the player's eyes while the terminal's CRT burns red with "I WARNED YOU" (`screen.warn`) → control returns with the ENTER THE HOLE objective), and the descent's last beat (`startDescentEnd` — the stairs themselves are walkable; main.js fires this only once the player has walked below `STATE.y<−8.5`, where the depth fog has already taken most vision: the view drifts on downward while the black closes, stone footsteps continue a few seconds, then hands off to `enterTheNest()` under the same black — the descent IS the level transition). - **`ui.js`** — DOM refs (`ui`), `toast`, objectives HUD (level-aware), overlay/pause logic, pointer lock, settings persistence (key + reader live in `settings.js`), mixer wiring.
- **`input.js`** — keyboard/mouse/pointer-lock listeners (side-effect module).
- **`main.js`** — imports everything and runs the `requestAnimationFrame` loop; dispatches `updateMonster` vs `updateSpider`+`updateLibrary` vs `updateSpiderCave`+`updateHatchlings`+`updateCave` on `STATE.level`; `updateLantern` and the descent/ascent cinematic triggers run here too.

THREE is a global (classic CDN `<script>` loads before the module graph) — modules do not import it.

There are intentional function-level circular imports (`monster ↔ lifecycle`, `ui ↔ lifecycle`, `cutscene ↔ lifecycle`, `spider ↔ lifecycle`, `library → ui → lifecycle → library`, `cave ↔ lifecycle`, `cave → ui → lifecycle → cave`, `spider → cave`/`spider → hatchling` one-way); they are safe because nothing in the cycle is called during module evaluation. Don't add top-level calls across these boundaries.

## Key conventions

- The map coordinate system uses `cellToWorld` / `worldToCell` (level 0), `cellToWorld2` / `worldToCell2` (THE END) and `cellToWorld3` / `worldToCell3` (THE NEST) to convert between grid cells (integers) and Three.js world space (meters). `CELL` (4m) is shared by all three.
- `MeshPhongMaterial` is used deliberately over `MeshLambertMaterial` on large floor/ceiling planes — Lambert is per-vertex in Three.js r128, which produces all-or-nothing lighting on geometry with only corner vertices.
- Light pool pattern: `LIGHT_POOL_N` point lights are reused each frame, bound to the nearest fixtures within `LIGHT_BIND_RADIUS`, instead of one light per fixture. All levels' fixtures share the same `lights`-record shape (library records add `fixY`/`wakeAt`; cave records add `cold`/`buzz:false`/`mul2`/`region`). `cold` records KEEP the idle breathe (it is the intended slow pulse) but never enter a flicker BURST: `canBurst` is gated on `!L.cold`. Strobing is a failing ballast, and a mushroom has not got one — the bursts were inherited from the electric floors and read as wrong on a plant. Fungus reacts only through `mul2`, the region die-back when a brood burns.
- Never change the scene's light COUNT at runtime — three.js r128 keys shader programs on it and recompiles everything in one frame (a hard hitch). Reveal-later lights (the library's hole, the cave's fissure and clutch fires, the lantern) are all created up front at intensity 0 and pre-warmed with `renderer.compile`.
- Exported `let` bindings (`grid`, `grid2`, `grid3`, `exitDoor`, `lights`, `interactables`) are reassigned/mutated by their owning module; importers see live values but must not assign to them.
- THE END's grid cell codes: 0 open · 1 wall · 2/3 shelf (along x/z) · 4 table · 5 desk. The spider treats every nonzero cell as solid; players pass type-4 cells only while crouched.
- THE NEST's grid cell codes: 0 open · 1 rock · 2 squeeze · 3 stream · 4 scree · 5 void · 6 bridge · 7 rubble. The matriarch treats 1/2/5/7 as solid; hatchlings pass squeezes (1/5/7 solid); players pass 2 only crouched and fall through 5.
